# عيب منصّي: قائمة المسارات البيضاء لمسار `file` لا تشمل `assets/pages/_conv/*` (وضع PHP)

**النوع:** عيب منصّة (سابق لتسليم مكتبة القوالب، اكتُشف أثناء الفحص الوظيفي لها)
**التاريخ:** 2026-11-13
**الحالة:** مؤجَّل — بانتظار قرار على مستوى المنصة. **لم يُعدَّل المستودع**؛ التخفيف طُبِّق على نسخة الاختبار فقط ومُفصَل عنها بوضوح.
**الأنظمة المتأثرة:** نسخة PHP فقط (`platform/php-edition`). وضع GitHub Pages غير متأثر (لا يمرّ عبر هذه القائمة أصلاً).

---

## 1. العَرَض

على متجر مثبَّت بالحزمة PHP، كل عمليات النشر من «مطوّر الصفحات» (PBConvert) تفشل:

- تحويل/نشر الرئيسية (`edit("home")` → `saveDirect`)
- تحويل/نشر صفحة منتج
- تحويل/نشر صفحة هبوط
- حفظ نسخة الاسترجاع الأولى

الواجهة تعرض: `PUT فشل (400) path_not_allowed`.

النتيجة العملية: **ميزة تحرير الصفحات معطّلة كلياً على الاستضافة PHP**، بينما تعمل على وضع GitHub.

## 2. السبب الجذري الدقيق

**النقطة الطرفية:** `api/index.php?r=file`
- القراءة GET: فحص القائمة في السطر **1002**
- الكتابة PUT: فحص القائمة في السطر **1011**
- القائمة نفسها: الدالة `allowedPath()` في السطر **229** من `platform/php-edition/api/index.php`

القائمة الحالية تسمح بـ:

| النمط | يغطي |
|---|---|
| `assets/js/data.js`, `assets/js/wilayas.js`, `index.html` | بيانات المتجر والرئيسية المنشورة |
| `assets/data/<name>.json` | ملفات البيانات |
| `p/<slug>/index[.x].html` | صفحات المنتجات المنشورة |
| `lp/<slug>/index.html` | صفحات الهبوط المنشورة |
| `assets/pages/<slug\|index>.json` | مصادر صفحات المنشئ (جذر assets/pages) |
| `assets/img/**.(webp|png|jpg|gif)` | الصور |

**لا تغطي** `assets/pages/_conv/<key>.json` (مصدر التحرير) ولا `assets/pages/_conv/<key>.orig.html` (نسخة الاسترجاع). لاحظ أن نمط `assets/pages/...` الحالي لا يطابقها لسببين: شرطة المسار الإضافية (`_conv/`)، والحرف `_` غير موجود في صنف الأحرف `[a-z0-9-]`.

مسارات PBConvert الفعلية (من `assets/js/admin-pb.js` — `saveDirect` ~11438):

| العملية | المسار | حالته في PHP |
|---|---|---|
| نسخة استرجاع أولى | `assets/pages/_conv/<key>.orig.html` | **400 مرفوض** |
| مصدر التحرير | `assets/pages/_conv/<key>.json` | **400 مرفوض** |
| هدف الرئيسية | `index.html` | مسموح ✓ |
| هدف منتج | `p/<slug>/index.html` | مسموح ✓ |
| هدف هبوط | `lp/<slug>/index.html` | مسموح ✓ |

أي أن الناتج المرئي للنشر قد يُكتب جزئياً (index.html مسموح) بينما يفشل مصدر التحرير ونسخة الاسترجاع — **حالة نصف-منشورة**: الصفحة تتغير لكن الاسترجاع والتحرير اللاحق ينكسران.

## 3. الأثر الأمني (لماذا لا يُوسَّع بصمت)

`allowedPath` هي **حدّ الأمان الوحيد للكتابة** في المسار (التعليق عليها حرفياً: «قائمة بيضاء لمسارات الكتابة — لا شيء خارجها»). أي توسيع يجب أن يكون:

1. **مُثبَتاً (anchored)** وبامتداد ثابت، وإلا أمكنت كتابة `*.php` أو ملفات تنفيذية → RCE على الاستضافة.
2. بصنف أحرف ضيق (`[a-z0-9-]`) وطول مقيد، اتساقاً مع بقية الأنماط (الحماية من `..` و`\0` موجودة أصلاً في رأس الدالة).
3. واعياً بأن `assets/pages/_conv/*.json` يصبح **قابلاً للقراءة العلنية** مثل `assets/pages/*.json` (محتواه تعريف الصفحة — نفس حساسية نظيره المسموح حالياً، فلا اعتراض).
4. لا تغيير على صلاحيات الدور: المسار نفسه يفرض `needOwner()` لغير المالك قبل الوصول للقائمة — يجب أن يبقى كذلك.

ملاحظة: الكتابة لهذه الملفات لا تمرّ بفحص MIME (ذاك مخصص للصور عبر `isImagePath`) — مقبول لأن الامتدادين المقترحين ثابتان (`.json` / `.orig.html`) ولا يُسمح بغيرهما.

## 4. الإصلاح المقترح (حدّ أدنى، سطران)

داخل `allowedPath()`، بعد نمط `assets/pages/...` الحالي:

```php
if (preg_match('#^assets/pages/_conv/[a-z0-9][a-z0-9-]{0,60}\.json$#', $p)) return true;        // مصادر تحرير PBConvert
if (preg_match('#^assets/pages/_conv/[a-z0-9][a-z0-9-]{0,60}\.orig\.html$#', $p)) return true; // نسخ الاسترجاع
```

لا حاجة لأي توسيع آخر: أهداف النشر (`index.html`, `p/…`, `lp/…`) مغطاة أصلاً.

## 5. اختبارات تراجع مطلوبة (تُضاف لحزمة اختبار المنصة)

بيئة: PHP 8.1 + خادم مدمج + حزمة مبنية بـ`scripts/make-template.py --target php` ومثبَّتة عبر install.php (نفس بيئة فحص القبول).

1. **نشر رئيسية:** تسجيل دخول المالك → PBConvert تحويل الرئيسية → حفظ. المتوقع بعد الإصلاح: `200` لكل من `PUT assets/pages/_conv/home.orig.html` و`PUT assets/pages/_conv/home.json` و`PUT index.html`. (قبل الإصلاح: 400 على الأوليين.)
2. **نشر منتج:** تحويل صفحة منتج `prod-a` → `PUT assets/pages/_conv/prod-prod-a.json` يعود 200.
3. **نشر هبوط:** تحويل lp → `PUT assets/pages/_conv/lp-<slug>.json` يعود 200.
4. **استرجاع:** `restore("home","")` يعيد `index.html` إلى بصمة SHA-256 السابقة للتثبيت (يتطلب وجود `.orig.html`).
5. **سلبي — امتداد:** `PUT assets/pages/_conv/evil.php` → 400؛ `PUT assets/pages/_conv/x.html` (ليس `.orig.html`) → 400.
6. **سلبي — اجتياز:** `PUT assets/pages/_conv/../admin.html` → 400 (مرفوض أصلاً بفحص `..`).
7. **سلبي — أحرف:** `PUT assets/pages/_conv/Ab_C.json` → 400 (خارج صنف الأحرف).
8. **صلاحية الدور:** موظف (غير مالك) يحاول PUT لمسار `_conv` مسموح → 401/403 من `needOwner()` قبل القائمة.
9. **عدم تراجع القائمة:** مسارات مسموحة حالياً (`assets/js/data.js`, `p/x/index.html`, `assets/data/store.json`, صورة في `assets/img/…`) تبقى 200.

## 6. ما فُعل في تسليم القوالب (إفصاح كامل)

- أثناء الفحص الوظيفي (23 تأكيداً) على حزمة PHP محلية، أُضيف السطران أعلاه إلى **نسخة الاختبار فقط** (`/tmp/store/api/index.php`) مع تعليق `TEST-FIXTURE ONLY: GitHub mode allows these`. **نسخة المستودع لم تُمسّ** — لا في `platform/php-edition/api/index.php` ولا في مولّد الحزم.
- بدون هذا التخفيف الاختباري كان يستحيل التحقق من ميكانيكية تثبيت/استرجاع القوالب على وضع PHP إطلاقاً.
- قرار دمج الإصلاح رسمياً (مع اختبارات التراجع أعلاه) متروك لمالك المنصة — خارج نطاق تسليم مكتبة القوالب.

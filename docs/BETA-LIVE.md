## بنية النشر
واجهة ساكنة تُبنى بـ`scripts/build-beta.py` (قالب نظيف + طبقة Beta) وتُخدَّم من Worker `alyssum-beta-web` يقرأ KV `alyssum-beta-web-files` (Pages لم يصلح: الرفع المباشر للأصول يحتاج JWT يتعارض مع وكيل الجلسة). الواجهة تتحدث مع Supabase Beta (دخول/طلبات/إعدادات اللوحة) ومع Worker Beta عبر دالة `platform-proxy` المنشورة على Supabase Beta (أسرارها: رابط Worker Beta ومفتاح متجر Beta، لا Production).

أدوات: `platform/api/tools/deploy.mjs --env beta` (db/worker/secrets) · `platform/api/tools/d1-migrate.mjs --env beta` · `platform/env/beta/deploy-static.mjs` (فرق ذكي؛ عند حدّ كتابة KV المجاني اليومي يُضمَّن المتغيّر في الـWorker مؤقتاً) · اختبارات التشغيل: `platform/env/beta/e2e/` (`api-e2e.mjs` و`ui-e2e.js` و`ui-start.js`).

## ما اختُبر فعلاً على الروابط الحيّة (لا محاكاة)
- **Worker وD1 Beta (API E2E، 25 فحصاً):** تسجيل متجرَين بدعوة، مفاتيح بنطاقات، مزامنة منتجات واسترجاعها، إنشاء طلب وعدم تكراره عند الإعادة، رفض هاتف غير صالح، تأكيد الطلب (حدث يُعالجه cron)، **عزل البيانات بين المتجرَين** (منتجات وطلبات)، رفض مفتاح المستأجر على مسارات الإدارة، تعطيل المتجر يوقف مفتاحه فوراً، `/health` يطابق (بيئة وقاعدة beta ومخطط).
- **المتصفح + Supabase Beta (UI E2E، 26 فحصاً):** عرض المتجر والمنتج، إنشاء طلب (`submit_order` حقيقي) وحفظه في قاعدة Beta دون تكرار، المبلغ يُحسب خادمياً، المجهول لا يقرأ/يعدّل/يحذف الطلبات ولا يقرأ `admin_kv`، كلمة مرور خاطئة ⇒ لا دخول، دخول المدير، ظهور الطلب في اللوحة وتأكيده وحفظ الحالة بعد إعادة التحميل، حفظ واسترجاع إعداد اللوحة، منتج من اللوحة إلى منصة Beta عبر الوسيط، الوسيط يمنع مسارات الإدارة ولا يعمل للمجهول، لا أخطاء JS ولا اتصال بمضيف خارج Beta (عدا الخطوط).
- **عدم الاتصال بـProduction:** ملفات الواجهة المنشورة بلا أي مرجع إنتاجي (مرجع Supabase الإنتاجي، مضيفا `alyssumhub.fyi`، مفتاح الإنتاج العام، مستودع المالك)؛ Workers Production وD1 Production لم تُعدَّل (آخر تعديل قبل 2026-11-17).

## أخطاء ظهرت أثناء الاختبار وأُصلحت
1. **لوحة التحكم لا تحمّل الطلبات بخلفية Supabase بلا رابط Apps Script** (`admin.html` كان يشترط `CONFIG.API_URL`): الطلبات في القاعدة لكن القائمة فارغة. أُصلح بشرط `API.ordersBackend() === "supabase"` (4 مواضع) + فحص `B8b`. *الإصلاح في كود مشترك مع العملاء — يحتاج قراراً قبل نقله إلى main.*
2. **`/admin` و`/VERSION` بـ404** ← الـWorker الساكن يدعم الروابط النظيفة، و`build-beta.py` يكتب `VERSION`.
3. **خط Cairo لا يُنسخ** (404) ← يُنسخ في البناء.
4. **صفحة بدء التجربة لا تصل المنصة (CORS)**: المسارات العامة بلا ترويسة CORS ← تُضاف لأصل واجهة البيئة نفسها فقط ولمسارات `/v1/beta/*` فقط (نجاحاً وخطأً)، والإنتاج بلا أثر (`M11` في `beta-module.test.mjs`).
5. بدء بناء Beta يتعارض مع متغيرات البيئة `BETA_SUPABASE_*` في اختبار `--allow-placeholder` (الاختبار يُشغَّل بدونها).

## قيود صريحة (لم تُختبر أو لا تعمل في Beta)
- **نشر المنتجات من لوحة التحكم (حفظ ونشر) غير متاح**: لوحة المتجر تحفظ الكتالوج والصفحات بالكتابة في مستودع GitHub (`GH.putFile`) وBeta بلا مستودع محتوى (وحجبه عن `saberbalbouzi-ui` مقصود). **المنتجات في Beta تُدار عبر المنصة (`/v1/catalog/products` ← يعمل ومُختبَر)**، والواجهة تعرض منتج `demo`. تفعيل «حفظ ونشر» يحتاج مستودع محتوى خاصاً بـBeta ورمز GitHub (إجراء منك).
- **بوابة الشحن (`alyssum-shipping-gateway-beta`) لم تُنشَر** ولا شركات توصيل (Sandbox فقط). Chargily Sandbox الحقيقي NOT TESTED (لا مفتاح). Chargily webhooks، البريد/SMS: محجوبة في Beta.
- **تسجيل متجر تجريبي**: الدعوات داخلية (مرحلة internal) والتسجيل محدود بـ5 محاولات/ساعة لكل IP. إنشاء دعوات جديدة يحتاج `ADMIN_TOKEN` (سرّ Worker Beta).
- لا نطاق مخصص ولا SSL مخصص ولا Cloudflare for SaaS (NOT TESTED). المضيفان `workers.dev` المثبَّتان في `platform/env/environments.json`.
- حدّ KV المجاني (حساب Production القديم): 1000 كتابة/يوم؛ الحساب الجديد قبل 1535 كتابة في نشر واحد. النشر فرق ذكي (يكتب المتغيّر فقط) ويضمّن الزائد في الـWorker عند بلوغ الحدّ.

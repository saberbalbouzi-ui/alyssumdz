# خطة الاستضافة متعددة المستأجرين (على نهج Shopify)

> قرار صاحب المتجر: دومين **جديد** مخصص للمنصة على Cloudflare، ويبقى `alyssumdz.com` (Hostinger → GitHub Pages) كما هو دون أي مسّ.
> الحالة: **خطة فقط، لم يُبنَ منها شيء بعد.** البنود المعلَّمة «⚠ للتحقق» أرقام/حدود لم تُراجَع من مصادر رسمية بعد.

## 1) المشكلة
- كل زبون = مستودع GitHub Pages مستقل: دومين واحد لكل مستودع، وشهادة SSL تُضبط يدوياً، ولا يتوسع.
- المطلوب: زبون يربط دومينه (أو يحصل على اسم فرعي من المنصة) فيعمل موقعه بشهادة تلقائية، دون تدخل يدوي منا.

## 2) المبدأ
استضافة واحدة تستقبل **كل** الدومينات، وتحدّد الزبون من اسم المضيف (`Host`):

```
زائر ──► دومين الزبون (CNAME) ──► Cloudflare (شهادة تلقائية، Custom Hostname)
                                    │
                                    ▼
                         Worker واحد «موزّع المستأجرين»
                         1) يقرأ Host   2) يبحث عنه في Supabase (saas_sites)
                         3) يجلب محتوى موقع الزبون من مصدره (المرحلة 1: مستودعه)
                         4) يخزّن مؤقتاً (cache) ويعيد الصفحة
```

- **دومين المنصة (جديد، يُشترى):** منطقة (zone) في Cloudflare. فيه `*.دومين-المنصة` للأسماء الفرعية (`اسم.دومين-المنصة`) و`مضيف التحويل` (fallback origin) الذي يوجّه إليه الزبائن بـCNAME.
- **دومين الزبون:** يضع الزبون سجل `CNAME` واحداً نحو مضيف التحويل (دومين فرعي)، أو سجلات A/CNAME حسب ما يعطيه Cloudflare لدومين الجذر. الشهادة تُصدَر وتتجدد تلقائياً.
- قاعدة البيانات والدوال تبقى على Supabase كما هي.

## 3) المراحل

| المرحلة | المحتوى | القبول |
|---|---|---|
| 0 | شراء دومين المنصة، نقل DNS له إلى Cloudflare، سرّ `CF_API_TOKEN` | المنطقة «نشطة»؛ `*.دومين` يردّ عبر Cloudflare |
| 1 | **الجسر:** Worker يوزّع بحسب `Host` ← `saas_sites` ← مصدر الموقع (مستودع الزبون الحالي). موقع تجريبي واحد | زيارة `تجربة.دومين-المنصة` تعرض الموقع بشهادة صحيحة؛ مضيف غير معروف يعرض صفحة «غير موجود» |
| 2 | **ربط الدومين برمجياً:** Edge Function `domains` (Supabase) تُنشئ/تفحص/تحذف Custom Hostname عبر Cloudflare API؛ أعمدة جديدة في `saas_sites`؛ بطاقة اللوحة تعرض حالة DNS والشهادة وتعليمات الـCNAME | زبون تجريبي يربط دومينه فيعمل بـHTTPS دون تدخلنا |
| 3 | **شراء الدومينات** (امتدادات عالمية) من اللوحة عبر API المسجِّل (Hostinger أو غيره بعد التحقق) بموافقة لكل عملية وعرض السعر قبل الدفع | شراء `.com` تجريبي وضبط DNS تلقائياً |
| 4 | نقل المحتوى من مستودع لكل زبون إلى مخزن مركزي (R2/Storage)؛ الزبائن الجدد عليه مباشرة | الموقع الجديد يعمل بلا مستودع |

الزبائن القدامى يبقون على GitHub Pages حتى تكتمل المرحلة 4؛ لا انقطاع.

## 4) تغييرات البيانات (مقترحة، تُضاف إلى `saas/schema.sql`)
- `saas_sites`: `host text unique` (الاسم الفرعي أو الدومين الفعّال)، `source text` (مصدر المحتوى)، `cf_hostname_id text`، `cf_status text`، `ssl_status text`، `cf_checked_at timestamptz`.
- دالة `saas_site_by_host(p_host)` (تُقرأ من الـWorker، تُرجع `source` والحالة ولا شيء آخر).
- ما يخص الإغلاق والاشتراك (`suspended`…) يطبّقه الـWorker من الحالة نفسها فلا يحتاج منطقاً جديداً.

## 5) الأسرار (تُوضع في بيئة/Secrets، لا في المستودع ولا في المحادثة)
- `CF_API_TOKEN`، `CF_ZONE_ID`، `CF_ACCOUNT_ID` — Supabase Edge Functions Secrets (لدالة `domains`).
- أسرار الـWorker في Cloudflare (قراءة `saas_site_by_host` بمفتاح عام فقط).
- `HOSTINGER_API_TOKEN` — فقط إن اعتُمد Hostinger لشراء الدومينات (المرحلة 3).

## 6) ما لا يمكن أتمتته
- **`.dz`**: يديره NIC.DZ بوثائق قانونية؛ لا API عالمي. الزبون يشتريه من مسجِّل محلي ثم يضع CNAME عندنا. لا نعد الزبائن بشراء `.dz` من اللوحة.
- **الدفع**: الطرق المتاحة لدى صاحب المتجر RedotPay (فيزا دولية) وPayPal. البطاقات المحلية غير مقبولة في الخدمات العالمية.

## 7) للتحقق قبل الاعتماد ⚠
1. تسعير Custom Hostnames (المجاني الأول ثم رسم لكل دومين) وهل يلزم وسيلة دفع محفوظة حتى للمجاني.
2. حدود Workers (الطلبات اليومية) وهل تُحسب الأصول الثابتة.
3. شروط GitHub Pages لتمرير الطلبات عبر وكيل (proxy) وحدود المعدل مع آلاف المواقع — قد يقودنا لتسريع المرحلة 4.
4. أن Cloudflare تقبل بطاقة RedotPay/PayPal للحساب.
5. أداء الاتصال من الجزائر (مسار الحركة الفعلي).
6. اسم الدومين الجديد للمنصة وتوفره.

## 8) المخاطر
- الاعتماد على مصدر GitHub في المرحلة 1 (حدود/شروط) ← نقل مبكّر للمحتوى المركزي.
- خطأ في الموزّع يؤثر على كل الزبائن ← بيئة تجريبية ونشر تدريجي، وصفحة تراجع.
- أي خلل في ربط الدومين لا يجب أن يمسّ `alyssumdz.com` (منطقة منفصلة تماماً).

## 9) المطلوب من صاحب المتجر
1. شراء دومين المنصة (من Hostinger أو غيره) وإخباري باسمه.
2. حساب Cloudflare مجاني، وإضافة الدومين إليه، وتغيير الـNameservers عند المسجِّل.
3. وضع `CF_API_TOKEN` (صلاحيات: DNS وSSL/Custom Hostnames لتلك المنطقة فقط) في الأسرار، وعدم لصقه في المحادثة.

# README الواجهة الرئيسية للمنصة — تكليف لـ ChatGPT (التصميم والصور والقالب)

> **تقسيم العمل:**
> - **أنت (ChatGPT)** تنشئ **الصور** و**القالب** (تصميم الصفحة الرئيسية كاملاً بـHTML وCSS ثابتين، جاهزاً بصرياً ومرتّباً).
> - **أنا (Claude)** أكتب **الكود** بعدك: السلوك (JavaScript)، الترجمة بثلاث لغات، التفاعلات، ربط النماذج، الأداء، والتكامل مع المنصة.
>
> لذلك **لا تكتب منطقاً برمجياً** (لا JavaScript)، بل سلّمني قالباً يحوي كل عناصر الواجهة وحالاتها ومعرّفات واضحة أبني عليها (القسم 8). هذا الملف هو المرجع الكامل: ما هي المنصة، لمن، هويتها، محتواها الحقيقي، ما يجوز قوله وما لا يجوز، ثم قائمة الصور المطلوبة بمواصفاتها وأوامر توليدها، ثم مواصفات القالب وطريقة التسليم.

**الهدف:** صفحة رئيسية تسويقية للمنصة (موقع تعريفي بصفحة واحدة قابلة للتوسّع لصفحات فرعية) موجَّهة إلى: تجّار المنتجات الفيزيائية، وبائعي المنتجات الرقمية، ومصمّمي الصور والمواقع المحترفين، وصنّاع المحتوى وأصحاب العلامات التجارية.

## 1) ما هي المنصة؟

منصة **SaaS لإدارة التجارة الإلكترونية وصناعة المحتوى البصري** في مكان واحد: يفتح التاجر لوحة تحكم واحدة، ينشئ موقعه ومتجره وصفحات البيع، يستقبل الطلبات ويؤكدها ويشحنها ويحصّل ماله ويحسب ربحه الحقيقي، ويصمّم صوره وإعلاناته وفيديوهاته ويدير حملاته — دون أن يتنقل بين عشرة تطبيقات.

**أركانها الستة:**
1. **متجر وصفحات بيع** — منشئ صفحات مرئي (سحب وإفلات)، 27 قالباً جاهزاً بحسب المجال، نموذج طلب بصفحة واحدة، سلة، عروض إضافية.
2. **تشغيل الطلبات** — مركز اتصال لتأكيد الطلبات، مخزون ومستودعات، شركات توصيل، مرتجعات، جرد، تجهيز وطباعة بوالص.
3. **المال والربح** — ربح حقيقي بعد التوصيل والمرتجعات والإعلانات، محفظة بضمان (Escrow)، دفع إلكتروني وتحويلات، خدمات تسويق جاهزة.
4. **ستوديو الصور والتصميم** — 15 أداة رئيسية (وأدوات مساندة) لتحرير صور المنتجات وتوليد المشاهد والفيديو والشعار والهوية البصرية ومعالجة مئات الصور دفعة واحدة.
5. **أسواق ونظام بيئي** — سوق توريد (دروبشيبينغ/جملة)، شبكة خبراء مستقلين (مصممون، مشترو إعلانات، مؤكّدات، موزّعون، صنّاع UGC)، متجر تطبيقات لمطوّرين مستقلين.
6. **API مفتوح للمطوّرين** — أحداث وWebhooks موقَّعة، OAuth، تكاملات (Meta/TikTok/Snapchat، واتساب، Google Sheets)، توثيق OpenAPI.

**اللغات والاتجاه:** الواجهة الأساسية عربية (RTL)، مع إمكانية الفرنسية والإنجليزية. المنصة **عالمية الطموح**: لا تُحصَر في سوق واحد ولا في نشاط واحد (عسل/تجميل مثلاً)؛ أمثلة الأسعار والتوصيل الجزائرية تُذكر فقط كمثال على عمق التكامل المحلي.

**اسم المنصة:** *لم يُحسم بعد.* استعمل المتغيّر `{{PLATFORM_NAME}}` في كل مكان، وشعاراً مؤقتاً نصياً. (المرشح الأقرب حالياً: «Tesave» — لا تعتمده نهائياً.)

## 2) الجمهور المستهدف — أربع شرائح

> لكل شريحة: **الرسالة** (جملة واحدة)، **الألم الذي نحلّه**، **ما تراه في المنصة**. يجب أن يعرض الموقع مدخلاً واضحاً لكل شريحة (تبويبات أو بطاقات أو أقسام)، مع مقطع مشترك للجميع.

### 2.1 تجّار المنتجات الفيزيائية (دروبشيبينغ، متاجر محلية، علامات صغيرة)
- **الرسالة:** «من إعلان الفيسبوك إلى تسليم الطرد وربحك الحقيقي — في لوحة واحدة.»
- **الألم:** طلبات الدفع عند الاستلام تضيع بين واتساب وجداول البيانات؛ نسب مرتجعات عالية؛ لا يعرف التاجر ربحه الفعلي بعد رسوم التوصيل والمرتجعات والإعلانات.
- **ما يراه:** مركز اتصال لتأكيد الطلبات بالدور مع أهداف يومية للمؤكّدات، توجيه تلقائي لشركة التوصيل الأنسب حسب المنطقة والأداء، بوالص مجمّعة وماسح باركود، مخزون متعدد المستودعات مع إرجاع تلقائي للمرتجع، قائمة سوداء للزبائن المشكوك فيهم، سلال متروكة، «الربح الحقيقي» مع إنفاق Meta/TikTok، أكواد خصم وعروض Bump/Upsell، سوق توريد للبيع بعمولة دون مخزون.

### 2.2 بائعو المنتجات الرقمية (اشتراكات، حسابات، مفاتيح تفعيل، ملفات، دورات)
- **الرسالة:** «بع مفاتيحك وملفاتك واشتراكاتك وتسلَّم الدفع واسلِّم المنتج تلقائياً — بلا توصيل ولا انتظار.»
- **الألم:** التسليم اليدوي بالواتساب، التحقق من تحويلات الدفع، نفاد مخزون المفاتيح دون تنبيه، لا رابط تنزيل آمن.
- **ما يراه:** متجر بنوع «رقمي» بلا ولايات ولا توصيل، مخزن مفاتيح مشفّر بمنع التكرار، تسليم تلقائي بعد تأكيد الدفع (بريد أو واتساب)، روابط تنزيل محدودة المدة والعدد، دفع بطاقة (Chargily) أو BaridiMob/CCP بإثبات تحويل يوافق عليه التاجر بنقرة، تنويعات (شهر/3 أشهر/سنة) بمخزون مستقل، تنبيهات نفاد المخزون.

### 2.3 مصمّمو الصور والمواقع المحترفون (فريلانسرز، استوديوهات، وكالات)
- **الرسالة:** «ستوديو كامل لتحرير صور المنتجات وتصميم الصفحات — اشتغل أسرع، سلِّم لعملائك أكثر، واربح من خبرتك.»
- **الألم:** تكرار نزع الخلفيات وتوحيد المقاسات؛ تسليم مئات الصور؛ أدوات متفرقة واشتراكات متعددة؛ صعوبة إيجاد عملاء.
- **ما يراه:** 15 أداة صور رئيسية (إزالة الخلفية، التقاط العناصر، حذف العناصر، تلوين، تغيير المقاس والتوسيع، مشاهد المنتج، تصوير المنتج، النموذج والتجربة الافتراضية، تحريك الصورة، شعار وهوية بصرية، معالجة دفعات، كتالوج) وأدوات مساندة، معالجة دفعات حتى 250 صورة بقالب معالجة موحّد، منشئ صفحات مرئي بقوالب ونسخ قوالب من مواقع أخرى، **شبكة الخبراء** (ملف عام وتقييمات وواتساب مباشر من التاجر)، **متجر التطبيقات** لبيع إضافاتهم وتقاسم الإيراد، وبيع خدمات للتجار داخل المنصة.

### 2.4 صنّاع المحتوى وأصحاب العلامات التجارية
- **الرسالة:** «هوية علامتك — ألوانها وخطها وشعارها — تُطبَّق على كل صورة وفيديو ومنشور وصفحة تلقائياً.»
- **الألم:** اتساق العلامة عبر المنصات، تكلفة التصميم، النشر المنتظم على السوشيال.
- **ما يراه:** الهوية البصرية المحفوظة (ألوان/خط/شعار) تُطبَّق على كل المخرجات، منشئ الشعار (نصي مجاني أو بالذكاء)، مولّد الصور والإعلانات بمقاسات كل المنصات والنشر المتعدد بنقرة، فيديو إعلاني من صورة بقوالب ستوري/ريلز، سوشيال: جدولة فيسبوك/إنستغرام بقوالب نصوص وتوليد نص ذكي، مدوّنة وSEO، مكتبة أصول (صور وأيقونات وفيديو بلا علامات مائية) وآلاف الملصقات، موقع متكامل بنطاق خاص.

## 3) الهوية البصرية (إلزامية)

### 3.1 الألوان
| الدور | القيمة | ملاحظة |
|---|---|---|
| خلفية داكنة أساسية | `#06130e` (و`#06120d`) | سطح الصفحة |
| خلفية ثانوية داكنة | `#0b2018` / `#0b1d15` | أقسام داكنة متناوبة |
| **اللون المميّز (Mint/ليموني)** | **`#c6fe17`** (RGB `198,254,23`) | الأزرار الأساسية، الروابط، الأيقونات، الشارات، التوهج الخفيف |
| أخضر المنصة العميق | `#173f35` | حدود، خلفيات أزرار على الأقسام الفاتحة |
| أخضر ثانوي | `#22c55e` / `#4ade80` | تدرجات الأزرار والمخططات |
| نص على الداكن | `#f3f8f4` (أساسي) · `#b8c9be` (ثانوي) | |
| قسم فاتح | خلفية `#f6f8f5` / `#ffffff` ونص `#10241b` وثانوي `#5a6b61` | أقسام التناوب |
| ألوان الحالات | برتقالي `#ffd45e` تنبيه · وردي-أحمر `#ff5d82` خطأ/حذف · أزرق `#5aa8ff` معلومة · سماوي `#3be6ff` · بنفسجي `#b79bff` | للمخططات والشارات فقط وبقدر قليل |

**قواعد:** الطابع العام **زجاج داكن أخضر** (Dark Glass): أسطح شبه شفافة بحدود رفيعة `rgba(255,255,255,.14)` وتمويه خلفية، وتدرجات خضراء هادئة في الزوايا. الليموني **للتمييز فقط** (لا تملأ مساحات كبيرة به). تناوب الأقسام الداكنة والفاتحة مسموح (انظر 3.5).

### 3.2 الخط
- **Cairo** (Google Fonts) بالأوزان 400/700/800/900 للعربية واللاتينية. بديل: `'Segoe UI', Tahoma, sans-serif`.
- العناوين الكبيرة وزن 900، العناوين الفرعية 800، النص 400–700. حجم العنوان الرئيسي `clamp(2rem, 5vw, 3.2rem)`، سطر النص 1.7–1.8.
- الاتجاه `dir="rtl"` و`lang="ar"` افتراضياً، مع دعم `ltr` للفرنسية/الإنجليزية عبر `dir` على الجذر.

### 3.3 المكوّنات
- **الأزرار — قاعدة ثابتة:** *زجاج شفاف منتفخ قليلاً بنص أبيض* دون لون صلب: أخضر/ليموني للأساسي، رمادي زجاجي للثانوي، برتقالي للتنبيه، أحمر للحذف. «منتفخ» = لمعة علوية داخلية + ظل داخلي سفلي + ظل خارجي خفيف + `backdrop-filter: blur`. التفاعل عند المرور = تلوين أقوى + `translateY(-2px)` **دون توهج مبالغ**. (انظر 3.5)
- **الشارات (pill):** نص ليموني صغير بحدّ ليموني شفاف وخلفية `rgba(198,254,23,.08)`.
- **البطاقات:** زوايا 16–20px، حدّ رفيع، ظل ناعم؛ على الداكن سطح زجاجي، على الفاتح أبيض بحدّ `#e3e9e3`.
- **الأيقونات:** خطّية (stroke 2، زوايا مستديرة)؛ **ممنوع الإيموجي** في الواجهة. استعمل SVG خطياً (Lucide/Tabler مسموحان — ترخيص MIT).
- **الحركة:** خفيفة وهادئة (ظهور عند التمرير، تحويم)، وتحترم `prefers-reduced-motion`.
- **شريط التمرير:** رفيع.

### 3.4 قواعد الصور (من صاحب المنصة — صارمة)
- بلا علامات مائية أو شعارات مواقع أو علامات تجارية ظاهرة.
- **لا امرأة بلا خمار** ولا جزء عارٍ من الجسم عدا الوجه واليدين. (يمكن عرض رجال بلباس كامل ونساء بخمار ولباس محتشم، أو الاكتفاء بالمنتجات والمشاهد والمانيكان.)
- لا نصوص مدمجة داخل الصور (النص يُكتب HTML حتى يُترجَم).
- صور المنتجات: خلفيات واقعية دافئة أو استوديو نظيف؛ ألوان المنتجات الطبيعية تتناغم مع الأخضر الداكن.

## 4) هيكل الصفحة الرئيسية المطلوب

> الترتيب مقترح؛ يجوز تحسينه بشرط بقاء كل الأقسام. كل قسم بعنوان + جملة + عناصر. **لا تخترع أرقاماً أو شهادات أو شعارات عملاء أو أسعاراً** (القسم 6).

1. **شريط علوي ثابت:** الشعار `{{PLATFORM_NAME}}` — روابط (المزايا، الأدوات، الشرائح، الأسئلة) — زر ثانوي «تسجيل الدخول» — زر أساسي «ابدأ مجاناً» (أو «اطلب عرضاً» حتى تُحسم الباقات) — مبدّل اللغة (ع / Fr / En).
2. **الهيرو:** عنوان قوي بنفَس «كل أدواتك — متجر، طلبات، شحن، ربح، وتصميم — في منصة واحدة»؛ فقرة؛ زرّان؛ ثلاث نقاط ثقة صادقة (مثلاً: «بالعربية RTL كاملة»، «بلا تثبيت»، «أدوات صور مجانية»)؛ **مشهد بصري كبير** (لقطة لوحة تحكم مصمّمة بالـHTML/CSS أو ولّد صورة لها) محاطاً بصور المنتجات العائمة من القسم 7 (`hero-02-products-floating`).
3. **اختر طريقك (الشرائح الأربع):** بطاقات/تبويبات كبيرة، لكل منها صورة، رسالة، 3–4 نقاط، رابط «اكتشف».
4. **كيف تعمل؟ (3–4 خطوات):** أنشئ متجرك ← أضف منتجاتك وصفحاتك ← استقبل الطلبات وأكّدها وأرسلها ← قِس ربحك الحقيقي وكبّر.
5. **لوحة التحكم في لمحة:** عرض بصري لمحاكاة اللوحة الداكنة (بطاقات إحصاء ليمونية، مخطط، جدول طلبات بشارات حالة) مع تعليقات توضيحية على 5–6 وحدات.
6. **ستوديو الصور والتصميم:** عرض الأدوات الـ15 الرئيسية ببطاقات (من جدول 5.8: الاسم وسطر وشارة «مجانية/ذكاء» وأيقونتها) مع شريط قبل/بعد من أزواج `studio-0x`، مع شريط قبل/بعد تفاعلي، وأزرار «جرّب».
7. **متجر ومنشئ صفحات وقوالب:** معرض 27 قالباً بحسب المجال (صور `store-0x-*-mock`) مع مرشّحات (أزياء، تجميل، عسل وأعشاب، مكملات، إلكترونيات، رقمي، مجوهرات، ساعات…).
8. **التشغيل والتوصيل والمال (للفيزيائي):** شبكة مزايا: مركز الاتصال، التوجيه الذكي، البوالص، المخزون والمرتجعات، الربح الحقيقي، المحفظة والضمان.
9. **المنتجات الرقمية:** قسم مستقل بمنطق «بع ← ادفع ← تسلَّم آلياً» مع مخطط مبسّط للتدفق.
10. **للمحترفين وصنّاع المحتوى:** شبكة الخبراء، متجر التطبيقات (للمطوّرين)، الهوية البصرية، سوشيال وفيديو، API وWebhooks.
11. **المنظومة المفتوحة (للمطوّرين):** بطاقة API/تكاملات/OAuth مع مقتطف كود وهمي واضح أنه مثال.
12. **لماذا نحن (التمايز):** عربية RTL أصيلة وتكامل محلي، كل شيء في لوحة واحدة، أدوات مجانية بلا ذكاء + ذكاء اختياري بتكلفة شفافة، ملكية بياناتك، أمان (2FA وأدوار وسجلّ نشاط).
13. **الباقات:** هيكل بطاقات **بلا أسعار** («قريباً/تواصل معنا») إلى أن تُحدَّد؛ ضع مكان السعر `{{PRICE}}`.
14. **أسئلة شائعة (8–10):** بإجابات صادقة (القسم 6).
15. **دعوة أخيرة + تذييل:** نموذج بريد/واتساب، روابط (المنتج، الأدوات، الموارد، قانوني)، حسابات التواصل `{{SOCIAL}}`.

### 5.1 لوحة التحكم (أقسامها حسب المجموعات)

لوحة داكنة زجاجية (ومظهر فاتح اختياري) بشريط جانبي وبحث سريع و«اسألني» (مساعد مدمج) وأوامر صوتية. المجموعات الخمس:

**الإعدادات العامة:** لوحة التحكم (نظرة عامة على المبيعات والطلبات والتنبيهات) · إعدادات الموقع (الاسم، الدومين، الاتصال، اللغة والتوقيت، **مواقعي** متعددة، حسابات التواصل) · تجهيز المتجر (قائمة جاهزية الإطلاق) · المدوّنة والسياسات (مقالات وصفحات الخصوصية والاسترجاع والشحن والشروط بقوالب جاهزة) · الفريق والأمان (أدوار، مصادقة ثنائية TOTP، سجل نشاط).

**المنتجات:** المنتجات (صور، أسعار، تنويعات، عروض، مخزون، سعر شراء) · الصفحات (صفحات هبوط وصفحة رئيسية وصفحات منتجات) · التصنيفات · السمات · التحليلات · التعديل الجماعي (أسعار وحقول عدة منتجات) · فحص المنتجات (جودة الصور والوصف والروابط بدرجة /100) · SEO (عناوين وأوصاف وبيانات المشاركة وفهرسة).

**المتجر (e-commerce):** الطلبات (بحث وفلاتر وعروض محفوظة وتحديد جماعي وإجراءات جماعية وفواتير A4 وبوالص A6 بباركود) · الطلبات المسجلة (طرود شركة التوصيل بحالتها الحقيقية) · **مركز الاتصال** · تجهيز الطلبات (دور أمين المخزن: قائمة جمع ووصل تجهيز) · المخزون والأرباح · المدفوعات · تكلفة المنتجات (من سعر شراء أو من وصفة مواد أولية) · **الربح الحقيقي** · المحفظة · التوجيه والبوردرو · شركات التوصيل · رسوم التوصيل (مناطق + استثناءات بلديات) · أكواد الخصم + عروض تلقائية · العروض الإضافية (Bump وUpsell) · العملاء (شرائح، VIP، وسوم) · المرتجعات · إعادة الشراء (رسائل واتساب) · الجرد والمخزون (حدود دنيا ومستودعات) · البكسلات (فيسبوك/تيك توك/جوجل) · السوشيال والإعلانات · التقارير · الزبائن الأوفياء · القائمة السوداء · شبكة الخبراء · خدمات التسويق · سوق التوريد · المنتجات الرقمية · متجر التطبيقات · استوديو التطبيقات (للمطوّرين) · مركز المتاجر (طلبات Shopify وWooCommerce وجداول Google في لوحة واحدة).

**المظهر:** مظهر لوحة التحكم (داكن/فاتح، لون وحجم خط) · مظهر الموقع (خطوط وألوان وشعار) · الهيدر · الفوتر · القوالب (مكتبة + ناسخ القوالب).

**التطبيقات:** مطوّر الصفحات · المطوّر الذكي (توليد صفحة) · أدوات تعديل الصور · ستوديو ديزاين (كل الأدوات بصفحة تعريف لكل أداة) · مولّد الصور · الوكيل الذكي (ردود جاهزة للزائر) · الوكيل الناطق (أفاتار بصوت) · اسألني (مساعد اللوحة) · ناسخ القوالب · الأيقونات العائمة (واتساب، اتصال، ماسنجر) · نموذج الطلب.


### 5.2 المتجر والواجهة الأمامية للزبون
- نموذج طلب **في صفحة واحدة** (الولاية ← البلدية ← رسم التوصيل فوراً مع تفصيل إضافة البلدية)، منزل أو مكتب Stop Desk، خريطة اختيار موقع اختيارية.
- سلة مشتريات، أكواد خصم متقدمة (حدود، فترات، منتجات/تصنيفات، مرة واحدة لكل هاتف، دمج)، عروض تلقائية (اشترِ X واحصل على Y)، Order Bump في صفحة المنتج وUpsell بعد الشراء، صفحة شكر.
- تنويعات وسمات، عروض كميات، شحن مجاني بشروط، مخزون منخفض «بقي N فقط».
- حسابات للزبائن، PWA (يُثبَّت كتطبيق)، مبدّل لغة وعملة، وضع الصيانة.
- الوكيل الذكي للزائر (يجيب عن الأسعار والتوصيل والتواصل) ورسائل واتساب جاهزة، أيقونات تواصل رسمية، زر مشاركة بنافذة الجهاز.
- SEO: روابط نظيفة، sitemap وJSON-LD وOG، مدوّنة، سياسات قانونية بقوالب.
- قياس: بكسلات + Conversions API من الخادم (Meta/TikTok/Snapchat)، تتبع مصدر الحملة (UTM وfbclid/ttclid)، A/B للصفحات بإحصاء z.

### 5.3 الطلبات والتوصيل
- **تأكيد الطلبات (CRM):** طابور بالدور، نتائج اتصال (تأكيد، لم يُجب 1–3، لاحقاً/غداً، رقم خاطئ، إلغاء بسبب)، تعديل العنوان مع التأكيد، قفل الطلب أثناء الاتصال، **أهداف يومية** لكل موظفة، توزيع الطلبات بين الموظفات (حصص/حسب الشركة/حسب الولاية/يدوي)، تنبيه تأخر، ترتيب الفريق، زمن أول استجابة.
- **شركات التوصيل:** ربط حسابات عبر مفاتيح API؛ ياليدين (مُتحقَّق منه فعلياً: إنشاء/تتبع/بوليصة/إلغاء) وZR Express وMaystro وNOEST وعائلة Ecotrack (تجريبية، تنتظر حسابات حقيقية)؛ أسعار تلقائية بتعريفة الشركة وإضافات البلديات؛ **توجيه تلقائي** بحسب المنطقة وأفضل نسبة تسليم؛ **إعادة توجيه** لشركة بديلة عند الرفض؛ إرسال جماعي وطباعة بوالص الشركة الأصلية؛ **محطة مسح** بالباركود وكشف تسليم؛ مزامنة الحالات تلقائياً؛ **فحص المفاتيح** استباقياً.
- **بوابة شحن مستقلة (API)** لتجميع الشركات خلف واجهة واحدة (REST + Webhooks موقَّعة) — تُباع كخدمة لمطوّرين خارج المنصة.
- **المخزون:** مستودعات متعددة وتوجيه الخصم حسب الولاية، حدود دنيا وتنبيهات، **إرجاع تلقائي للمرتجع** عند وصوله للبائع، جرد بسجل حركة، ربط المخزون بالطلبات (يعرف أي طلب خارج المخزون)، سلة مهملات للطلبات.
- **المرتجعات:** طلب/موافقة/استلام/استرداد أو استبدال مع مهلة وتخزين مرتجع سليم أو تالف.
- **الجداول:** لكل جدول تحديد وقائمة Action (طباعة، CSV، Excel).

### 5.4 المال والربح
- **الربح الحقيقي:** المحصَّل فعلاً من الطرود المسلَّمة − كلفة البضاعة − التوصيل − التغليف − خسارة المرتجعات − المستردّات − **الإعلان الفعلي من Meta وTikTok** − مصاريف ثابتة؛ مؤشرات (نسبة التسليم، CPA وROAS الحقيقيان)، جدول حملات وولايات، **ربط حساب فيسبوك الإعلاني بنقرة** (OAuth) لسحب الإنفاق تلقائياً.
- **تسوية شركة التوصيل:** مطابقة كشف الدفع، حساب الرسوم الحقيقية (COD، تأمين، إرجاع).
- **دورة حياة الحملة:** إيقاف الحملة وأرشفتها وربطها بالأرباح والمخزون وتنبيه نفاد المخزون أثناء حملة نشطة.
- **المحفظة:** رصيدك على المنصة (متاح · ضمان · قيد السحب · رصيد إعلانات بالدولار) بدفتر **قيد مزدوج** غير قابل للتعديل؛ ضمان Escrow يُحرَّر عند التسليم؛ طلبات سحب (CCP، BaridiMob، بنك، RedotPay، PayPal)؛ شراء رصيد إعلانات بالدولار.
- **الدفع:** رابط دفع إلكتروني بالبطاقة (Chargily Pay)، حوالات BaridiMob/CCP بإثبات صورة وموافقة يدوية، شحن المحفظة.
- **خدمات التسويق (White Label):** اشترِ حساباً إعلانياً (TikTok/Meta) جاهزاً بالدينار من محفظتك؛ المبلغ يُحجز ضماناً ويصلك رابط الدعوة عند التسليم.

### 5.5 المنتجات الرقمية
مخزن مفاتيح وحسابات مشفّر (بصمة تمنع التكرار) · تسليم تلقائي عند `payment.confirmed` · ملفات برابط محدود · بريد أو واتساب · طرق دفع: بطاقة/BaridiMob/CCP · إثبات تحويل بصورة (JPEG/PNG/WebP) وموافقة بنقرة · تنويعات بمخزون مستقل · تنبيهات المخزون المنخفض · لوحة «الرئيسية الرقمية» · لا ولايات ولا توصيل.

### 5.6 الأسواق والنظام البيئي
- **سوق التوريد:** مورّد يُدرج منتجاً بسعر جملة وعمولة؛ تاجر يستورده بنقرة ويبيعه بسعره؛ **عمولة تُحجز من رصيد المورّد وتُحرَّر عند التسليم** (حماية للطرفين)؛ بوابة للمورّدين الخارجيين وأنواع «جملة/تجزئة».
- **شبكة الخبراء:** دليل مستقلين بملف عام وتقييمات موثّقة وشارة «موثّق» وبحث بتخصص وولاية وسعر؛ تواصل واتساب مباشر؛ مساحة المستقل بمفتاح سرّي.
- **متجر التطبيقات:** تثبيت تطبيقات مطوّرين بصلاحيات مغلقة يوافق عليها التاجر، **بيانات الزبائن مقنَّعة افتراضياً**، OAuth 2.0، اشتراكات وتقاسم إيراد (عمولة المنصة 20% افتراضياً)، تقييمات واسترداد 7 أيام؛ **استوديو المطوّر** لإنشاء التطبيقات ومتابعة التسليمات والإيرادات.
- **مركز المتاجر:** تجميع طلبات Shopify وWooCommerce وجداول Google من كل متاجرك للقراءة والاستيراد.

### 5.7 مطوّر الصفحات والقوالب

#### 01 — Suppression de fond | إزالة الخلفية

##### الهدف
عزل الموضوع الرئيسي أو الموضوعات المحددة من الصورة، وإخراج صورة بخلفية شفافة أو استبدال الخلفية بخيار آخر.

##### طريقة الاستخدام
1. يرفع المستخدم صورة.
2. تظهر معاينة الصورة الأصلية.
3. يضغط «إزالة الخلفية».
4. يرسل التطبيق الصورة إلى محرك إزالة الخلفية المتاح.
5. تظهر النتيجة فوق خلفية مربعات شفافية، مع خيار عرض الأصل والنتيجة جنبًا إلى جنب.
6. يمكن للمستخدم اختيار خلفية معاينة: شفافة، لون ثابت، أو صورة خلفية إذا كانت هذه الميزة منفذة.
7. ينزّل النتيجة بصيغة PNG للحفاظ على الشفافية، أو بصيغة أخرى عند اختيار خلفية غير شفافة.

##### عناصر الواجهة
- رفع صورة / استبدال الصورة.
- زر «إزالة الخلفية».
- مؤشر تقدم وحالة المعالجة.
- معاينة شفافية.
- مقارنة قبل/بعد.
- تنزيل PNG؛ ولا تعرض صيغة لا يدعمها التصدير الفعلي.
- خيار «إعادة المحاولة» عند الفشل.

##### متطلبات الدقة
- الحفاظ قدر الإمكان على الشعر والحواف الدقيقة والشفافية الجزئية.
- عدم قص أجزاء من المنتج أو الشخص.
- إذا كانت النتيجة ضعيفة، اعرضها بوضوح ولا تدّعِ الكمال.
- لا تُزل الخلفية محليًا بطريقة بدائية ثم تسمّها «ذكاء اصطناعي».

##### اختبارات
منتج على خلفية بيضاء، شخص، شعر، زجاج/عبوة شفافة، صورة مزدحمة، صورة لا تحتوي موضوعًا واضحًا.


#### 02 — Générateur d'images | مولّد الصور

##### الهدف
إنشاء صورة جديدة من وصف نصي، خصوصًا مشاهد وصور تجارية مناسبة للمتاجر والإعلانات.

##### طريقة الاستخدام
1. يكتب المستخدم وصف الصورة.
2. يختار نسبة الأبعاد أو المقاس من الخيارات المدعومة.
3. يختار نمطًا أو نوع المشهد إن كان متاحًا.
4. يضغط «إنشاء الصورة».
5. تظهر حالة التوليد، ثم النتيجة أو النتائج.
6. يمكنه تنزيل صورة، أو إعادة التوليد، أو تعديل الوصف.

##### عناصر الواجهة
- حقل وصف نصي متعدد الأسطر.
- اختيارات مقاس/نسبة أبعاد مدعومة فعليًا.
- اختيار عدد النتائج فقط إذا كان المحرك يدعم ذلك.
- زر «إنشاء».
- عرض النتيجة مع أزرار تنزيل وإعادة توليد.
- تحذير من التكلفة قبل التنفيذ إذا كان ذلك متاحًا من API.

##### متطلبات
- أرسل الوصف إلى خدمة توليد صور حقيقية.
- لا تعرض صورة ثابتة على أنها مولّدة لحظيًا.
- لا تضف كتابة أو شعارًا على الصورة تلقائيًا إلا إذا طلب المستخدم ذلك صراحة.
- حافظ على وصف المنتج الأصلي عند توليد مشهد حول منتج إذا كانت الخدمة تدعم مرجع صورة.


#### 03 — Photographie de produit IA | تصوير المنتجات بالذكاء الاصطناعي

##### الهدف
تحويل صورة منتج موجودة إلى صورة منتج احترافية بإضاءة وتكوين وخلفية استوديو، مع الحفاظ على هوية المنتج قدر الإمكان.

##### طريقة الاستخدام
1. يرفع المستخدم صورة المنتج.
2. يحدد نوع المنتج أو يتركه للاكتشاف إذا كانت هذه الميزة متاحة.
3. يختار خلفية أو بيئة تصوير أو نمط إضاءة.
4. يحدد نسبة الصورة أو منصة النشر إذا كانت الخيارات متاحة.
5. يضغط «إنشاء صورة المنتج».
6. يعاين النتيجة ويقارنها بالأصل ثم ينزّلها.

##### خيارات ممكنة
- استوديو أبيض نظيف.
- إضاءة ناعمة فاخرة.
- مشهد تجاري/أسلوب حياة.
- لقطة قريبة للمنتج.
- صورة كتالوج بخلفية بسيطة.

لا تعرض هذه الخيارات إلا إذا كان محرك التوليد يستطيع تنفيذها فعلًا.

##### ضوابط مهمة
- لا تغيّر لون المنتج أو شكله أو عدد أجزائه أو علامته التجارية دون قصد.
- لا تضف نصًا غير مطلوب إلى العبوة.
- اعرض تنبيهًا بأن الصور التوليدية قد تغيّر تفاصيل دقيقة، وأنها تحتاج مراجعة قبل نشرها تجاريًا.
- لا تخلط هذه الأداة مع «Mise en scène du produit»: الأولى تركّز على تصوير المنتج كصورة احترافية، والثانية تركّز على وضع المنتج في خلفية/مشهد أسلوب حياة.


#### 04 — Modèle virtuel | النموذج الافتراضي

##### الهدف
عرض قطعة ملابس على نموذج افتراضي لتقديم تصور تسويقي عن شكلها، مع احترام صورة المنتج قدر الإمكان.

##### طريقة الاستخدام
1. يرفع المستخدم صورة الملابس أو يختارها من منتجاته.
2. يختار نموذجًا افتراضيًا من النماذج المتاحة، أو يرفع صورة نموذج إذا كان ذلك مسموحًا ومدعومًا.
3. يختار وضعية أو إطارًا بصريًا إذا كان المحرك يدعم ذلك.
4. يضغط «إنشاء المعاينة».
5. يراجع النتيجة وينزّلها.

##### اعتبارات الواجهة
- معرض واضح للنماذج مع معاينة قبل الاختيار.
- خيارات ملابس/نوع منتج عند دعمها.
- لا تفترض وجود إعدادات للجنس أو العمر أو المقاس ما لم تكن موجودة فعلًا.
- يمكن اعتماد نماذج نسائية محجبات ضمن المعرض عند الحاجة، مع تنوع محترم وطبيعي.

##### ضوابط
- لا تدّعِ أن النتيجة تمثل المقاس أو الملاءمة الفعلية للملابس.
- لا تغيّر تصميم الملابس أو نقوشها أو ألوانها دون توضيح.
- إذا لم تتوفر خدمة التجربة على نموذج، اعرض «قريبًا» بدل صورة مزيفة.


#### 05 — Essayage virtuel | التجربة الافتراضية

##### الهدف
إنتاج معاينة افتراضية لقطعة ملابس أو إكسسوار على صورة شخص أو نموذج، إذا كان محرك التجربة الافتراضية يدعم نوع المنتج.

##### طريقة الاستخدام
1. يرفع المستخدم صورة الشخص أو يختار نموذجًا افتراضيًا.
2. يرفع صورة قطعة الملابس أو يختارها من كتالوجه.
3. يراجع متطلبات الصورة: وضوح الجسم، الوضعية، والإضاءة وفق المحرك.
4. يضغط «جرّب افتراضيًا».
5. ينتظر المعالجة، ثم يقارن النتيجة بالأصل.
6. ينزّل النتيجة عند رضاه.

##### الواجهة
- خطوة منفصلة لصورة الشخص وخطوة لصورة المنتج.
- أمثلة مرئية لمواصفات الصور المناسبة.
- مؤشر معالجة ورسائل أخطاء مفهومة.
- مقارنة قبل/بعد.
- حذف صور الرفع من مساحة العمل وفق سياسة الخصوصية المعتمدة.

##### ضوابط
- لا تَعِد بمقاس دقيق أو محاكاة واقعية كاملة.
- لا تستخدم صورًا لأشخاص دون حق استخدامها.
- لا تخلط بين هذه الأداة و«Modèle virtuel»: النموذج الافتراضي يستخدم نموذجًا جاهزًا لعرض الملابس، بينما التجربة الافتراضية تحاول إظهار قطعة على صورة الشخص/النموذج الذي اختاره المستخدم.
- يجب أن يعتمد توفر أنواع المنتجات على قدرات الخدمة الحقيقية.


#### 06 — Mise en scène du produit | وضع المنتج في مشهد

##### الهدف
إدماج صورة منتج في مشهد أسلوب حياة أو بيئة مناسبة، مثل عطر بين الزهور، أو كرسي في غرفة معيشة، أو منتج تجميلي في حمام أنيق.

##### طريقة الاستخدام
1. يرفع المستخدم صورة المنتج، ويفضل أن تكون واضحة ومفصولة عن الخلفية.
2. يختار فئة أو وصفًا للمشهد المطلوب.
3. يحدد المزاج/البيئة/الإضاءة إذا كانت مدعومة.
4. يضغط «إنشاء المشهد».
5. يعاين النتيجة ويتحقق من شكل المنتج والظلال.
6. ينزّل الصورة.

##### خيارات محتملة
- استوديو بسيط.
- منزل/غرفة معيشة.
- طبيعة ونباتات.
- حمام/عناية شخصية.
- مكتب/تقنية.
- مطبخ/أطعمة.

##### ضوابط
- حافظ على المنتج باعتباره العنصر الأساسي.
- لا تضف نصوصًا أو شعارات غير مطلوبة.
- إذا كان فصل المنتج وتركيبه يتمان عبر نموذج توليدي، وضّح أن التفاصيل قد تختلف.
- لا تكرر صورة واحدة في كل أمثلة الصفحة.


#### 07 — Générateur de vidéo | مولّد الفيديو

##### الهدف
إنشاء فيديو قصير من صورة منتج أو صورة ثابتة باستخدام حركة كاميرا أو حركة مولدة، حسب المحرك المتاح.

##### طريقة الاستخدام
1. يرفع المستخدم الصورة.
2. يكتب وصف الحركة أو يختار حركة جاهزة مدعومة.
3. يختار مدة الفيديو ونسبة الأبعاد فقط إذا كان المحرك يدعمها.
4. يضغط «إنشاء الفيديو».
5. تظهر حالة المعالجة ونتيجتها.
6. يعاين الفيديو، ثم ينزّله بصيغة يدعمها المحرك.

##### عناصر الواجهة
- رفع صورة.
- وصف الحركة.
- خيارات الحركة/المدة/المقاس حسب دعم الخدمة.
- معاينة فيديو مع تشغيل/إيقاف.
- زر تنزيل.
- تنبيه تكلفة قبل التنفيذ إن توفرت التكلفة الحقيقية.

##### ضوابط
- لا تعرض صورة ثابتة أو حركة CSS على أنها فيديو مولد إذا لم يكن هذا هو المقصود.
- لا تعد بمدة أو دقة أو صوت غير مدعوم.
- إذا كانت الأداة الحالية تحرّك الصورة بحركة تقريب/تحريك فقط، سمّها بوضوح «تحريك الصورة» ولا توحِ بأنها توليد فيديو كامل بالذكاء الاصطناعي.


#### 08 — Redimensionner et agrandir | تغيير المقاس والتوسيع

##### الهدف
تغيير أبعاد الصورة إلى مقاسات مناسبة لقنوات النشر، مع إمكانية توسيع مساحة الصورة خارج حدودها الأصلية لتوليد أجزاء جديدة من المشهد عندما تكون خدمة التوسيع متاحة.

##### وضعا العمل
**أ. تغيير المقاس**
1. يختار المستخدم نسبة جاهزة أو يدخل العرض والارتفاع.
2. يحدد الحفاظ على النسبة الأصلية أو السماح بالتغيير إذا كان مناسبًا.
3. يختار ملاءمة الصورة: احتواء كامل، ملء مع قص، أو تمديد غير موصى به.
4. يعاين النتيجة قبل التنزيل.

**ب. توسيع الصورة بالذكاء الاصطناعي**
1. يحدد المستخدم اتجاه التوسيع أو يسحب حدود الإطار للخارج.
2. يختار مساحة التوسيع.
3. يضغط «توليد الامتداد».
4. تظهر خيارات النتائج إذا كان المحرك يعيد أكثر من نتيجة.
5. تُعرض الصورة الأصلية داخل النتيجة بحيث لا يُستبدل المنتج الأصلي أو يُعاد توليده قدر الإمكان.

##### عناصر الواجهة
- مقاسات منصات شائعة فقط إذا كانت محددة ومحدثة.
- حقول عرض وارتفاع.
- قفل نسبة الأبعاد.
- إطار قابل للسحب للتوسيع عند دعم هذه الوظيفة.
- معاينة وقبل/بعد.

##### ضوابط
- لا تخلط التكبير البكسلي التقليدي مع التوسيع التوليدي؛ اشرح الفرق.
- تحقق من الحدود القصوى للأبعاد التي تدعمها الخدمة.
- تجنب تشويه المنتج.


#### 09 — Supprimer des objets | حذف العناصر

##### الهدف
حذف عنصر غير مرغوب فيه من الصورة، ثم إعادة بناء المنطقة التي كان يشغلها بما يتناسب مع الخلفية المحيطة.

##### طريقة الاستخدام
1. يرفع المستخدم صورة.
2. يحدد العنصر بفرشاة، أو أداة تحديد، أو شكل هندسي وفق الواجهة المتاحة.
3. يستطيع تعديل حجم الفرشاة وإضافة/إزالة مناطق التحديد.
4. يضغط «حذف العنصر».
5. يعالج المحرك المنطقة، ثم تعرض النتيجة.
6. يقارن الأصل بالنتيجة، ويكرر التحديد إذا بقيت آثار.

##### عناصر الواجهة
- فرشاة بحجم قابل للتغيير.
- مسح التحديد وإعادة البدء.
- تكبير/تصغير الصورة.
- زر حذف.
- قبل/بعد، تراجع وإعادة.
- رسالة عند عدم القدرة على إعادة بناء خلفية معقدة.

##### ضوابط
- هذه الأداة تحذف العنصر من الصورة؛ لا تنقل العنصر إلى مكان آخر. نقل العنصر هو وظيفة Capture d'objet.
- لا تستخدم أداة إزالة الخلفية كبديل لحذف عنصر من وسط الصورة.
- لا تدّعِ نتيجة نظيفة دائمًا، خاصة مع الأنماط الدقيقة أو الخلفيات المعقدة.


#### 10 — Recolorer des vêtements et objets | إعادة تلوين الملابس والأشياء

##### الهدف
تغيير لون جزء محدد من الصورة مع المحافظة على الظلال والملمس والتفاصيل قدر الإمكان، أو إنتاج عدة نسخ لونية للمنتج.

##### طريقة الاستخدام
1. يرفع المستخدم الصورة.
2. يحدد العنصر/المنطقة المراد تلوينها.
3. يختار اللون من منتقي ألوان أو يدخل قيمة HEX إذا كان ذلك مدعومًا.
4. يعاين اللون الجديد ويعدّل شدته عند توفر هذا التحكم.
5. يضغط «تطبيق اللون» أو «إنشاء نسخة».
6. يمكنه حفظ عدة نسخ بألوان مختلفة.

##### عناصر الواجهة
- منتقي ألوان.
- ألوان مقترحة/لوحة ألوان.
- أداة تحديد المنطقة.
- معاينة قبل/بعد.
- إنشاء نسخ متعددة إذا كانت الميزة منفذة.

##### ضوابط
- حافظ على الظلال والطيّات والملمس.
- لا تغيّر لون الخلفية أو أجزاء أخرى خارج التحديد.
- اشرح أن الألوان على الشاشة قد تختلف عن اللون الحقيقي للمنتج.
- لا تدّعِ دقة مطابقة اللون المادي أو الطباعة.


#### 11 — Identité visuelle | الهوية البصرية

##### الهدف
إدارة مجموعة أصول العلامة التجارية في مكان واحد، مثل الشعار والألوان والخطوط، لتسهيل استخدامها في تصميمات المتجر والتسويق.

##### الوظائف الأساسية
- إضافة شعار أو أكثر ورفع ملفات الشعار.
- حفظ لوحة ألوان العلامة، بما فيها قيم HEX.
- حفظ أسماء الخطوط واستخداماتها، مع التأكد من توفر الخطوط وترخيصها.
- حفظ اسم العلامة ووصف مختصر عند الحاجة.
- اختيار هوية محفوظة وتطبيق ألوانها وخطوطها على تصميم إذا كان المحرر يدعم ذلك.
- تعديل الهوية وحذفها وتحديد الهوية النشطة.

##### طريقة الاستخدام
1. يفتح المستخدم «إنشاء هوية».
2. يضيف اسم العلامة وشعارها وألوانها وخطوطها.
3. يشاهد معاينة للوحة الهوية.
4. يحفظها.
5. يختارها عند تصميم صورة أو قالب متوافق.

##### ضوابط
- هذه الأداة لإدارة الهوية، وليست بالضرورة مولّد شعار؛ مولّد الشعار أداة مستقلة.
- لا تُطبّق التغييرات على ملفات قديمة تلقائيًا دون تأكيد.
- لا تستخدم خطوطًا أو شعارات محمية دون حق استخدام.
- إذا لم يكن ربط الهوية بالمحرر منفذًا، اجعلها مكتبة أصول فقط ووضّح ذلك.


#### 12 — Créateur de logo | منشئ الشعارات

##### الهدف
مساعدة المستخدم على إنشاء أفكار شعارات أولية، ثم تخصيص الرمز والألوان والنص والتكوين وتنزيل النتيجة بصيغ مناسبة.

##### طريقة الاستخدام
1. يدخل اسم العلامة التجارية.
2. يضيف وصفًا اختياريًا للنشاط أو شخصية العلامة.
3. يختار أسلوبًا بصريًا أو ألوانًا عند توفر الخيارات.
4. يضغط «إنشاء أفكار».
5. يختار فكرة ويخصص النص واللون والحجم والترتيب إذا كانت أدوات التحرير متاحة.
6. يعاين الشعار على خلفية فاتحة وداكنة.
7. ينزّل الصيغ التي يدعمها النظام.

##### خيارات واجهة ممكنة
- بسيط، هندسي، فاخر، طبيعي، تقني.
- لوحة ألوان.
- رمز/أيقونة.
- اسم العلامة وشعارها النصي.
- خلفية شفافة إذا كان التصدير يدعمها.
- تنزيل PNG أو SVG فقط إذا كان كل تنسيق يولّد بصورة صحيحة.

##### ضوابط
- لا تَعِد بأن الشعار حصري أو مسجل قانونيًا.
- لا تدّعِ إنشاء SVG متجهي حقيقي إذا كانت النتيجة مجرد صورة نقطية داخل ملف SVG.
- أظهر تنبيهًا بأن على المستخدم التحقق من التشابه والعلامات التجارية قبل الاستخدام الرسمي.
- لا تستخدم شعارات علامات مشهورة كقوالب جاهزة.


#### 13 — Traitement par lots | المعالجة الجماعية

##### الهدف
تطبيق نفس الإجراء أو مجموعة إعدادات على عدة صور دفعة واحدة، بدل تكرار العمل لكل صورة يدويًا.

##### طريقة الاستخدام
1. يختار المستخدم عدة صور أو يسحب مجموعة ملفات إلى منطقة الرفع.
2. يعرض النظام قائمة الصور المصغرة وحالة كل ملف.
3. يختار الإجراء الجماعي المتاح، مثل تغيير المقاس أو الصيغة أو تحسينات محددة أو إزالة الخلفية إذا كان المحرك يدعمها.
4. يحدد الإعدادات المشتركة.
5. يشاهد ملخصًا قبل التنفيذ.
6. يضغط «بدء المعالجة».
7. تظهر حالة كل صورة بشكل مستقل: في الانتظار، قيد المعالجة، ناجحة، فاشلة.
8. يستطيع إعادة محاولة الملفات الفاشلة فقط.
9. ينزّل الصور منفردة أو كملف ZIP إذا كان إنشاء ZIP مدعومًا.

##### متطلبات
- لا تعالج آلاف الصور دفعة واحدة دون حدود تقنية معروفة؛ استخدم دفعات/طوابير حسب النظام.
- أظهر العدد الإجمالي والناجح والفاشل.
- لا تفقد الملفات الناجحة إذا فشل ملف واحد.
- لا تُعد إرسال الملف نفسه عدة مرات بسبب إعادة المحاولة.
- اعرض تقديرًا للتكلفة فقط عند وجود بيانات أسعار فعلية.
- وضّح الإجراءات المدعومة جماعيًا؛ ليست كل أداة فردية بالضرورة قابلة للتشغيل الجماعي.


#### 14 — Catalogue de produits | كتالوج المنتجات

##### الهدف
تنظيم صور منتجات المتجر وتجهيزها للعرض ككتالوج بصري متناسق، مع ربط الصورة بالمنتج إذا كانت بيانات الكتالوج متاحة.

##### الوظائف المقترحة
- استيراد صور أو اختيار صور منتجات من مكتبة المتجر.
- عرض المنتجات في شبكة مع صورة مصغرة واسم/معرّف المنتج عند توفر البيانات.
- تصنيف المنتجات حسب الفئة.
- توحيد مقاس الصور ونسب الأبعاد.
- معاينة الصورة الأساسية والصور البديلة.
- تطبيق إعدادات موحدة على مجموعة صور إذا كانت المعالجة الجماعية مدعومة.
- تنزيل الصور أو تصدير قائمة/حزمة إذا كان النظام يدعم ذلك.

##### طريقة الاستخدام
1. يختار المستخدم صور المنتجات أو يربط الكتالوج الموجود.
2. تظهر شبكة المنتجات.
3. يختار فئة أو مجموعة.
4. يحدد إعدادات الصور المشتركة.
5. يعاين النتائج.
6. يعتمد التعديلات وينزّلها أو يحفظها في الكتالوج إذا كان الربط منفذًا.

##### ضوابط
- لا تخترع أسماء أو أسعارًا أو SKU للمنتجات.
- لا تغيّر الصور الأصلية في قاعدة البيانات دون تأكيد.
- فرّق بين «كتالوج صور» و«إدارة كتالوج تجارة إلكترونية كاملة»؛ لا تدّعِ إدارة المخزون أو الأسعار إذا لم تكن موجودة.
- وضّح حالة كل صورة وأي منتج لا توجد له صورة.


#### 15 — Capture d'objet | التقاط عنصر من الصورة

##### الهدف
تمكين المستخدم من اختيار عنصر داخل صورة، وفصله عن موضعه الأصلي، ثم نقله أو تغيير حجمه أو تدويره بشكل مستقل، مع الحفاظ على الخلفية الأصلية قدر الإمكان. هذه الوظيفة مختلفة عن إزالة الخلفية وحذف العناصر.

##### الفرق بين الأدوات
- **Capture d'objet:** يعزل عنصرًا داخل الصورة ليصبح قابلًا للتحريك والتعديل؛ يُفترض معالجة المكان الذي تركه العنصر في الخلفية.
- **Suppression de fond:** يزيل الخلفية من الموضوع الرئيسي أو المحدد.
- **Supprimer des objets:** يحذف عنصرًا غير مرغوب فيه ويعيد بناء المنطقة التي كان يشغلها.

##### طريقة الاستخدام
1. يرفع المستخدم صورة غير موجودة داخل إطار/شبكة، إذا كان محرك الالتقاط لا يدعم الصور المؤطرة.
2. يختار «تحديد بالنقر» ثم ينقر على العنصر، أو يختار «الفرشاة» ويرسم فوقه.
3. يمكنه إضافة عناصر متعددة للتحديد أو إزالة مناطق غير صحيحة.
4. يضغط «التقاط العنصر».
5. يفصل المحرك العنصر عن الخلفية وينشئ طبقة مستقلة.
6. تُعالج المنطقة التي كان العنصر يشغلها لإعادة بناء الخلفية، إن كان المحرك يدعم ذلك.
7. يظهر العنصر كطبقة قابلة للسحب والتحريك وتغيير الحجم والتدوير.
8. يستطيع المستخدم تكرار العنصر أو حذفه من التصميم إذا كانت هذه الوظائف متاحة.
9. يضغط «تطبيق» ثم يحفظ نسخة جديدة أو ينزّلها.

- تحديد بالنقر.
- فرشاة تحديد بحجم قابل للتغيير.
- تكبير وتحريك مساحة العمل.
- مسح التحديد وإعادة البدء.
- التقاط العنصر.
- مقابض لتغيير الحجم والتدوير.
- سحب العنصر بالماوس أو اللمس.
- تراجع/إعادة.
- مقارنة قبل/بعد.
- إعادة الصورة إلى الحالة الأصلية.

##### متطلبات تقنية
- حافظ على إحداثيات التحديد عند التكبير والتحريك.
- اجعل التحكم مناسبًا للفأرة واللمس.
- لا تسمح بتمرير الصفحة أثناء السحب داخل مساحة العمل على الهاتف إذا كان ذلك يفسد التفاعل.
- اعرض حدود العنصر المحدد بوضوح.
- إذا كان فصل العنصر أو ملء الخلفية يعتمد على API، فاعرض حالة المعالجة والأخطاء والتكلفة الفعلية قبل التنفيذ.
- لا تستخدم مجرد مستطيل قصّ حول العنصر وتسمّه التقاطًا ذكيًا.
- لا تعرض نتيجة وهمية. إذا كانت الميزة غير موصولة بمحرك الفصل وإعادة بناء الخلفية، اعرض «قريبًا» أو نفّذ واجهة اختيار فقط بوضوح.
- لا تعد بأن كل عنصر في كل صورة قابل للاستخراج بدقة كاملة.

## 8) القالب المطلوب منك (تصميم HTML/CSS ثابت — بلا JavaScript)

### 8.1 الملفات
```
template/
├─ index.html        ← الصفحة كاملة بكل الأقسام الـ15 (القسم 4)
├─ styles.css        ← كل الأنماط (يبدأ برموز 3.5)
└─ assets/…          ← الصور المولَّدة + icons.svg
```
HTML/CSS خام بلا أطر عمل (بلا Bootstrap/Tailwind)، يعمل بفتح `index.html` مباشرة.

### 8.2 مواصفات التصميم
- **RTL أولاً** (`<html lang="ar" dir="rtl">`)؛ استعمل خصائص منطقية (`margin-inline`, `inset-inline`) كي ينقلب التخطيط تلقائياً في الفرنسية والإنجليزية.
- **متجاوب:** جوال 360px، تابلت 768px، مكتب 1280px+؛ بلا تمرير أفقي؛ شبكات `grid`/`flex` لا قيم ثابتة مكسورة.
- **التباين ≥ 4.5:1**؛ الليموني نصاً على الأبيض ممنوع؛ حالات `:hover` و`:focus-visible` و`:active` لكل زر ورابط وبطاقة؛ `prefers-reduced-motion` يُلغي الحركة.
- **الحركة:** انتقالات CSS فقط (hover، تلاشٍ عند الظهور بفئة `.is-visible` أضيفها أنا بالسكربت). لا حركة مفرطة.
- **الأيقونات:** من `icons.svg` عبر `<svg><use href="assets/icons.svg#name"/></svg>`. لا إيموجي في الواجهة.
- **الأداء:** صور بـ`width`/`height` و`loading="lazy"` (عدا الهيرو `fetchpriority="high"`)، و`<picture>` لو أضفت نسخ صغيرة، وخط Cairo `display=swap`.
- **الأقسام:** نفّذ كل أقسام القسم 4 بالترتيب، بعناوين وجمل وعناصر **حقيقية من القسم 5** (لا لوريم). النصوص بالعربية الفصحى المبسّطة بنبرة واثقة ومباشرة.
- **القالب يُمثّل لوحة التحكم بالـHTML/CSS** (بطاقات إحصاء، مخطط SVG بسيط، جدول طلبات بشارات حالة) لا بصورة، في قسم «لوحة التحكم في لمحة»؛ ويُستعمل `hero-01` للهيرو.

### 8.3 معرّفات للكود (ليسهل عليّ ربط السلوك)
ضع هذه السمات في الأماكن المناسبة (أنا أكتب الـJS لاحقاً):
| العنصر | السمة المطلوبة |
|---|---|
| كل نص قابل للترجمة | `data-i18n="section.key"` ونصه العربي بداخله (مثل `data-i18n="hero.title"`) |
| الأقسام | `id` بالاسم: `hero audiences how panel studio templates ops digital pros api why plans faq cta` |
| روابط التنقل | `href="#id"` لكل قسم |
| مبدّل اللغة | أزرار `data-lang="ar|fr|en"` |
| تبويبات الشرائح الأربع | أزرار `role="tab" data-tab="physical|digital|designers|creators"` ولوحات `role="tabpanel" data-panel="…"` (كلها مرسومة في HTML، غير النشطة `hidden`) |
| شريط قبل/بعد | عنصر `data-compare` فيه صورتان `data-before` و`data-after` ومقبض `data-handle` |
| مرشّحات القوالب | أزرار `data-filter="all|fashion|cosmetics|honey|digital|tech|jewelry"` وبطاقات `data-cat="…"` |
| الأسئلة الشائعة | `<details><summary>` (أو `data-accordion`) |
| النماذج | `<form data-form="signup|contact">` بحقول `name` واضحة، وزر `type="submit"`، ورسالة حالة `data-form-status` |
| الظهور عند التمرير | الفئة `reveal` على العناصر |
| العدّادات (إن وُجدت) | `data-count-to` — **بلا أرقام مخترعة**، استعمل `{{STAT}}` |

### 8.4 عناصر نائبة (لا تخترع)
استعمل حرفياً: `{{PLATFORM_NAME}}` اسم المنصة (غير محسوم) · `{{PRICE}}` · `{{STAT}}` · `{{TESTIMONIAL}}` · `{{SOCIAL}}` · `{{DEMO_URL}}`، وروابط `#signup` و`#login`. الشعار مؤقتاً نصي بخط Cairo 900 مع رمز بسيط.

# ALYSSUM — دليل تنفيذ أدوات الصور الـ15
## مواصفات وظيفية وواجهة استخدام موجهة إلى Claude

**الهدف:** استخدام هذا الملف كمرجع تنفيذ لبناء 15 أداة ضمن منصة التجارة الإلكترونية Alyssum. يجب أن تكون كل أداة مستقلة وظيفيًا، ذات واجهة واضحة، وتجربة متجاوبة بالعربية RTL، مع قابلية إضافة الفرنسية والإنجليزية لاحقًا.

**الأدوات المشمولة:** 14 أداة ظاهرة في الصور المرفقة، إضافة إلى أداة Capture d'objet (التقاط عنصر من الصورة)، أي 15 أداة.

---

# 1. تعليمات عامة إلزامية إلى Claude

1. افحص المستودع الحالي قبل تعديل أي شيء. تعرّف على إطار العمل، نظام التوجيه، نظام التصميم، إدارة الملفات، المصادقة، تخزين الصور، واجهات API الموجودة، ومتغيرات البيئة.
2. **لا تُعد بناء التطبيق من الصفر** ولا تستبدل التقنيات الحالية دون ضرورة. التزم بالبنية الموجودة وأنماط المكونات والتسمية.
3. أنشئ صفحة مستقلة لكل أداة، إضافة إلى بطاقات دخول إليها في مركز الأدوات. لا تجعل صفحات الأدوات مجرد صور أو نماذج شكلية؛ اربط الأزرار بسلوك حقيقي.
4. لا تدّعِ أن ميزة ذكاء اصطناعي تعمل إذا لم تكن موصولة بنموذج أو خدمة فعلية. إذا لم تتوفر خدمة المعالجة، اعرض حالة «غير مفعّلة» أو «قريبًا» بوضوح، ولا تعرض نتيجة وهمية على أنها نتيجة حقيقية.
5. اجعل النصوص قابلة للترجمة ومنفصلة عن الصور. **لا تُنشئ صورًا تحتوي على نصوص مدمجة**؛ استخدم HTML/CSS للنصوص والعناوين والأزرار.
6. الواجهة الأساسية عربية RTL، متجاوبة للهاتف واللوحي والحاسوب، مع حالات تحميل، نجاح، خطأ، إلغاء، إعادة محاولة، وتأكيد قبل العمليات غير القابلة للتراجع.
7. حافظ على الصورة الأصلية دون تغيير. أنشئ نسخة عمل لكل عملية، مع إمكانية «تراجع»، «إعادة»، «إعادة ضبط»، و«تنزيل النتيجة».
8. لا تستبدل ملف المستخدم الأصلي تلقائيًا. اعرض معاينة قبل/بعد، واحتفظ بالأصل طوال الجلسة أو وفق سياسة التخزين الحالية.
9. تحقق من نوع الملف وحجمه وأبعاده قبل الرفع، وتعامل مع الملفات غير المدعومة ورسائل API والأوقات المستغرقة.
10. لا تخترع أسعارًا أو حدودًا أو صيغًا مدعومة. إذا كانت الخدمة تتطلب مفتاح Alyssum API، اعرض التكلفة المتوقعة **قبل التنفيذ** فقط إذا كانت متوفرة من واجهة الأسعار الفعلية؛ لا تحسب أسعارًا تخمينية.
11. استخدم مكونات مشتركة قدر الإمكان: رفع صورة، منطقة عمل، معاينة قبل/بعد، شريط أدوات، سجل العمليات، تنبيه، نافذة تنزيل، ومؤشر تقدم.
12. احترم حقوق الصور وخصوصية المستخدم. لا ترسل الصور إلى مزود خارجي إلا عبر تكامل مقصود وواضح، ولا تسجل مفاتيح API في المتصفح أو السجلات.
13. لا تضع مسارات أو أزرارًا ميتة. اربط كل زر بوظيفته، أو عطّله مع سبب واضح.
14. في كل أداة، وثّق ما إذا كانت المعالجة محلية، أو عبر خادم Alyssum، أو عبر مزود ذكاء اصطناعي. لا تخلط بين واجهة العرض ومحرك المعالجة.
15. اختبر الحالات الأساسية، ومنها: صورة عمودية وأفقية ومربعة، صورة كبيرة، خلفية شفافة، خطأ شبكة، إلغاء العملية، وإعادة التحميل.

## نمط صفحة الأداة

- مسار مقترح: `/tools/<tool-slug>` (عدّله حسب نظام التوجيه الموجود).
- عنوان الأداة ووصف موجز.
- زر «رفع صورة» أو «اختيار صور».
- مساحة معاينة واضحة، مع مقارنة قبل/بعد عند ملاءمتها.
- أدوات التحكم على الجانب أو أسفل المعاينة حسب حجم الشاشة.
- قسم «كيف تعمل؟» مختصر.
- زر الإجراء الرئيسي: «ابدأ المعالجة» أو «جرّب الآن».
- أزرار: «تراجع»، «إعادة»، «إعادة ضبط»، «تنزيل».
- رسائل صريحة عند عدم تفعيل محرك المعالجة.
- قسم أسئلة شائعة أو مساعدة، إذا كان مفيدًا.

# 2. قائمة الأدوات

## 01 — Suppression de fond | إزالة الخلفية

### الهدف
عزل الموضوع الرئيسي أو الموضوعات المحددة من الصورة، وإخراج صورة بخلفية شفافة أو استبدال الخلفية بخيار آخر.

### طريقة الاستخدام
1. يرفع المستخدم صورة.
2. تظهر معاينة الصورة الأصلية.
3. يضغط «إزالة الخلفية».
4. يرسل التطبيق الصورة إلى محرك إزالة الخلفية المتاح.
5. تظهر النتيجة فوق خلفية مربعات شفافية، مع خيار عرض الأصل والنتيجة جنبًا إلى جنب.
6. يمكن للمستخدم اختيار خلفية معاينة: شفافة، لون ثابت، أو صورة خلفية إذا كانت هذه الميزة منفذة.
7. ينزّل النتيجة بصيغة PNG للحفاظ على الشفافية، أو بصيغة أخرى عند اختيار خلفية غير شفافة.

### عناصر الواجهة
- رفع صورة / استبدال الصورة.
- زر «إزالة الخلفية».
- مؤشر تقدم وحالة المعالجة.
- معاينة شفافية.
- مقارنة قبل/بعد.
- تنزيل PNG؛ ولا تعرض صيغة لا يدعمها التصدير الفعلي.
- خيار «إعادة المحاولة» عند الفشل.

### متطلبات الدقة
- الحفاظ قدر الإمكان على الشعر والحواف الدقيقة والشفافية الجزئية.
- عدم قص أجزاء من المنتج أو الشخص.
- إذا كانت النتيجة ضعيفة، اعرضها بوضوح ولا تدّعِ الكمال.
- لا تُزل الخلفية محليًا بطريقة بدائية ثم تسمّها «ذكاء اصطناعي».

### اختبارات
منتج على خلفية بيضاء، شخص، شعر، زجاج/عبوة شفافة، صورة مزدحمة، صورة لا تحتوي موضوعًا واضحًا.

## 02 — Générateur d'images | مولّد الصور

### الهدف
إنشاء صورة جديدة من وصف نصي، خصوصًا مشاهد وصور تجارية مناسبة للمتاجر والإعلانات.

### طريقة الاستخدام
1. يكتب المستخدم وصف الصورة.
2. يختار نسبة الأبعاد أو المقاس من الخيارات المدعومة.
3. يختار نمطًا أو نوع المشهد إن كان متاحًا.
4. يضغط «إنشاء الصورة».
5. تظهر حالة التوليد، ثم النتيجة أو النتائج.
6. يمكنه تنزيل صورة، أو إعادة التوليد، أو تعديل الوصف.

### عناصر الواجهة
- حقل وصف نصي متعدد الأسطر.
- اختيارات مقاس/نسبة أبعاد مدعومة فعليًا.
- اختيار عدد النتائج فقط إذا كان المحرك يدعم ذلك.
- زر «إنشاء».
- عرض النتيجة مع أزرار تنزيل وإعادة توليد.
- تحذير من التكلفة قبل التنفيذ إذا كان ذلك متاحًا من API.

### متطلبات
- أرسل الوصف إلى خدمة توليد صور حقيقية.
- لا تعرض صورة ثابتة على أنها مولّدة لحظيًا.
- لا تضف كتابة أو شعارًا على الصورة تلقائيًا إلا إذا طلب المستخدم ذلك صراحة.
- حافظ على وصف المنتج الأصلي عند توليد مشهد حول منتج إذا كانت الخدمة تدعم مرجع صورة.

---

## 03 — Photographie de produit IA | تصوير المنتجات بالذكاء الاصطناعي

### الهدف
تحويل صورة منتج موجودة إلى صورة منتج احترافية بإضاءة وتكوين وخلفية استوديو، مع الحفاظ على هوية المنتج قدر الإمكان.

### طريقة الاستخدام
1. يرفع المستخدم صورة المنتج.
2. يحدد نوع المنتج أو يتركه للاكتشاف إذا كانت هذه الميزة متاحة.
3. يختار خلفية أو بيئة تصوير أو نمط إضاءة.
4. يحدد نسبة الصورة أو منصة النشر إذا كانت الخيارات متاحة.
5. يضغط «إنشاء صورة المنتج».
6. يعاين النتيجة ويقارنها بالأصل ثم ينزّلها.

### خيارات ممكنة
- استوديو أبيض نظيف.
- إضاءة ناعمة فاخرة.
- مشهد تجاري/أسلوب حياة.
- لقطة قريبة للمنتج.
- صورة كتالوج بخلفية بسيطة.

لا تعرض هذه الخيارات إلا إذا كان محرك التوليد يستطيع تنفيذها فعلًا.

### ضوابط مهمة
- لا تغيّر لون المنتج أو شكله أو عدد أجزائه أو علامته التجارية دون قصد.
- لا تضف نصًا غير مطلوب إلى العبوة.
- اعرض تنبيهًا بأن الصور التوليدية قد تغيّر تفاصيل دقيقة، وأنها تحتاج مراجعة قبل نشرها تجاريًا.
- لا تخلط هذه الأداة مع «Mise en scène du produit»: الأولى تركّز على تصوير المنتج كصورة احترافية، والثانية تركّز على وضع المنتج في خلفية/مشهد أسلوب حياة.

## 04 — Modèle virtuel | النموذج الافتراضي

### الهدف
عرض قطعة ملابس على نموذج افتراضي لتقديم تصور تسويقي عن شكلها، مع احترام صورة المنتج قدر الإمكان.

### طريقة الاستخدام
1. يرفع المستخدم صورة الملابس أو يختارها من منتجاته.
2. يختار نموذجًا افتراضيًا من النماذج المتاحة، أو يرفع صورة نموذج إذا كان ذلك مسموحًا ومدعومًا.
3. يختار وضعية أو إطارًا بصريًا إذا كان المحرك يدعم ذلك.
4. يضغط «إنشاء المعاينة».
5. يراجع النتيجة وينزّلها.

### اعتبارات الواجهة
- معرض واضح للنماذج مع معاينة قبل الاختيار.
- خيارات ملابس/نوع منتج عند دعمها.
- لا تفترض وجود إعدادات للجنس أو العمر أو المقاس ما لم تكن موجودة فعلًا.
- يمكن اعتماد نماذج نسائية محجبات ضمن المعرض عند الحاجة، مع تنوع محترم وطبيعي.

### ضوابط
- لا تدّعِ أن النتيجة تمثل المقاس أو الملاءمة الفعلية للملابس.
- لا تغيّر تصميم الملابس أو نقوشها أو ألوانها دون توضيح.
- إذا لم تتوفر خدمة التجربة على نموذج، اعرض «قريبًا» بدل صورة مزيفة.

---

## 05 — Essayage virtuel | التجربة الافتراضية

### الهدف
إنتاج معاينة افتراضية لقطعة ملابس أو إكسسوار على صورة شخص أو نموذج، إذا كان محرك التجربة الافتراضية يدعم نوع المنتج.

### طريقة الاستخدام
1. يرفع المستخدم صورة الشخص أو يختار نموذجًا افتراضيًا.
2. يرفع صورة قطعة الملابس أو يختارها من كتالوجه.
3. يراجع متطلبات الصورة: وضوح الجسم، الوضعية، والإضاءة وفق المحرك.
4. يضغط «جرّب افتراضيًا».
5. ينتظر المعالجة، ثم يقارن النتيجة بالأصل.
6. ينزّل النتيجة عند رضاه.

### الواجهة
- خطوة منفصلة لصورة الشخص وخطوة لصورة المنتج.
- أمثلة مرئية لمواصفات الصور المناسبة.
- مؤشر معالجة ورسائل أخطاء مفهومة.
- مقارنة قبل/بعد.
- حذف صور الرفع من مساحة العمل وفق سياسة الخصوصية المعتمدة.

### ضوابط
- لا تَعِد بمقاس دقيق أو محاكاة واقعية كاملة.
- لا تستخدم صورًا لأشخاص دون حق استخدامها.
- لا تخلط بين هذه الأداة و«Modèle virtuel»: النموذج الافتراضي يستخدم نموذجًا جاهزًا لعرض الملابس، بينما التجربة الافتراضية تحاول إظهار قطعة على صورة الشخص/النموذج الذي اختاره المستخدم.
- يجب أن يعتمد توفر أنواع المنتجات على قدرات الخدمة الحقيقية.

## 06 — Mise en scène du produit | وضع المنتج في مشهد

### الهدف
إدماج صورة منتج في مشهد أسلوب حياة أو بيئة مناسبة، مثل عطر بين الزهور، أو كرسي في غرفة معيشة، أو منتج تجميلي في حمام أنيق.

### طريقة الاستخدام
1. يرفع المستخدم صورة المنتج، ويفضل أن تكون واضحة ومفصولة عن الخلفية.
2. يختار فئة أو وصفًا للمشهد المطلوب.
3. يحدد المزاج/البيئة/الإضاءة إذا كانت مدعومة.
4. يضغط «إنشاء المشهد».
5. يعاين النتيجة ويتحقق من شكل المنتج والظلال.
6. ينزّل الصورة.

### خيارات محتملة
- استوديو بسيط.
- منزل/غرفة معيشة.
- طبيعة ونباتات.
- حمام/عناية شخصية.
- مكتب/تقنية.
- مطبخ/أطعمة.

### ضوابط
- حافظ على المنتج باعتباره العنصر الأساسي.
- لا تضف نصوصًا أو شعارات غير مطلوبة.
- إذا كان فصل المنتج وتركيبه يتمان عبر نموذج توليدي، وضّح أن التفاصيل قد تختلف.
- لا تكرر صورة واحدة في كل أمثلة الصفحة.

## 07 — Générateur de vidéo | مولّد الفيديو

### الهدف
إنشاء فيديو قصير من صورة منتج أو صورة ثابتة باستخدام حركة كاميرا أو حركة مولدة، حسب المحرك المتاح.

### طريقة الاستخدام
1. يرفع المستخدم الصورة.
2. يكتب وصف الحركة أو يختار حركة جاهزة مدعومة.
3. يختار مدة الفيديو ونسبة الأبعاد فقط إذا كان المحرك يدعمها.
4. يضغط «إنشاء الفيديو».
5. تظهر حالة المعالجة ونتيجتها.
6. يعاين الفيديو، ثم ينزّله بصيغة يدعمها المحرك.

### عناصر الواجهة
- رفع صورة.
- وصف الحركة.
- خيارات الحركة/المدة/المقاس حسب دعم الخدمة.
- معاينة فيديو مع تشغيل/إيقاف.
- زر تنزيل.
- تنبيه تكلفة قبل التنفيذ إن توفرت التكلفة الحقيقية.

### ضوابط
- لا تعرض صورة ثابتة أو حركة CSS على أنها فيديو مولد إذا لم يكن هذا هو المقصود.
- لا تعد بمدة أو دقة أو صوت غير مدعوم.
- إذا كانت الأداة الحالية تحرّك الصورة بحركة تقريب/تحريك فقط، سمّها بوضوح «تحريك الصورة» ولا توحِ بأنها توليد فيديو كامل بالذكاء الاصطناعي.

## 08 — Redimensionner et agrandir | تغيير المقاس والتوسيع

### الهدف
تغيير أبعاد الصورة إلى مقاسات مناسبة لقنوات النشر، مع إمكانية توسيع مساحة الصورة خارج حدودها الأصلية لتوليد أجزاء جديدة من المشهد عندما تكون خدمة التوسيع متاحة.

### وضعا العمل
**أ. تغيير المقاس**
1. يختار المستخدم نسبة جاهزة أو يدخل العرض والارتفاع.
2. يحدد الحفاظ على النسبة الأصلية أو السماح بالتغيير إذا كان مناسبًا.
3. يختار ملاءمة الصورة: احتواء كامل، ملء مع قص، أو تمديد غير موصى به.
4. يعاين النتيجة قبل التنزيل.

**ب. توسيع الصورة بالذكاء الاصطناعي**
1. يحدد المستخدم اتجاه التوسيع أو يسحب حدود الإطار للخارج.
2. يختار مساحة التوسيع.
3. يضغط «توليد الامتداد».
4. تظهر خيارات النتائج إذا كان المحرك يعيد أكثر من نتيجة.
5. تُعرض الصورة الأصلية داخل النتيجة بحيث لا يُستبدل المنتج الأصلي أو يُعاد توليده قدر الإمكان.

### عناصر الواجهة
- مقاسات منصات شائعة فقط إذا كانت محددة ومحدثة.
- حقول عرض وارتفاع.
- قفل نسبة الأبعاد.
- إطار قابل للسحب للتوسيع عند دعم هذه الوظيفة.
- معاينة وقبل/بعد.

### ضوابط
- لا تخلط التكبير البكسلي التقليدي مع التوسيع التوليدي؛ اشرح الفرق.
- تحقق من الحدود القصوى للأبعاد التي تدعمها الخدمة.
- تجنب تشويه المنتج.

## 09 — Supprimer des objets | حذف العناصر

### الهدف
حذف عنصر غير مرغوب فيه من الصورة، ثم إعادة بناء المنطقة التي كان يشغلها بما يتناسب مع الخلفية المحيطة.

### طريقة الاستخدام
1. يرفع المستخدم صورة.
2. يحدد العنصر بفرشاة، أو أداة تحديد، أو شكل هندسي وفق الواجهة المتاحة.
3. يستطيع تعديل حجم الفرشاة وإضافة/إزالة مناطق التحديد.
4. يضغط «حذف العنصر».
5. يعالج المحرك المنطقة، ثم تعرض النتيجة.
6. يقارن الأصل بالنتيجة، ويكرر التحديد إذا بقيت آثار.

### عناصر الواجهة
- فرشاة بحجم قابل للتغيير.
- مسح التحديد وإعادة البدء.
- تكبير/تصغير الصورة.
- زر حذف.
- قبل/بعد، تراجع وإعادة.
- رسالة عند عدم القدرة على إعادة بناء خلفية معقدة.

### ضوابط
- هذه الأداة تحذف العنصر من الصورة؛ لا تنقل العنصر إلى مكان آخر. نقل العنصر هو وظيفة Capture d'objet.
- لا تستخدم أداة إزالة الخلفية كبديل لحذف عنصر من وسط الصورة.
- لا تدّعِ نتيجة نظيفة دائمًا، خاصة مع الأنماط الدقيقة أو الخلفيات المعقدة.

## 10 — Recolorer des vêtements et objets | إعادة تلوين الملابس والأشياء

### الهدف
تغيير لون جزء محدد من الصورة مع المحافظة على الظلال والملمس والتفاصيل قدر الإمكان، أو إنتاج عدة نسخ لونية للمنتج.

### طريقة الاستخدام
1. يرفع المستخدم الصورة.
2. يحدد العنصر/المنطقة المراد تلوينها.
3. يختار اللون من منتقي ألوان أو يدخل قيمة HEX إذا كان ذلك مدعومًا.
4. يعاين اللون الجديد ويعدّل شدته عند توفر هذا التحكم.
5. يضغط «تطبيق اللون» أو «إنشاء نسخة».
6. يمكنه حفظ عدة نسخ بألوان مختلفة.

### عناصر الواجهة
- منتقي ألوان.
- ألوان مقترحة/لوحة ألوان.
- أداة تحديد المنطقة.
- معاينة قبل/بعد.
- إنشاء نسخ متعددة إذا كانت الميزة منفذة.

### ضوابط
- حافظ على الظلال والطيّات والملمس.
- لا تغيّر لون الخلفية أو أجزاء أخرى خارج التحديد.
- اشرح أن الألوان على الشاشة قد تختلف عن اللون الحقيقي للمنتج.
- لا تدّعِ دقة مطابقة اللون المادي أو الطباعة.

## 11 — Identité visuelle | الهوية البصرية

### الهدف
إدارة مجموعة أصول العلامة التجارية في مكان واحد، مثل الشعار والألوان والخطوط، لتسهيل استخدامها في تصميمات المتجر والتسويق.

### الوظائف الأساسية
- إضافة شعار أو أكثر ورفع ملفات الشعار.
- حفظ لوحة ألوان العلامة، بما فيها قيم HEX.
- حفظ أسماء الخطوط واستخداماتها، مع التأكد من توفر الخطوط وترخيصها.
- حفظ اسم العلامة ووصف مختصر عند الحاجة.
- اختيار هوية محفوظة وتطبيق ألوانها وخطوطها على تصميم إذا كان المحرر يدعم ذلك.
- تعديل الهوية وحذفها وتحديد الهوية النشطة.

### طريقة الاستخدام
1. يفتح المستخدم «إنشاء هوية».
2. يضيف اسم العلامة وشعارها وألوانها وخطوطها.
3. يشاهد معاينة للوحة الهوية.
4. يحفظها.
5. يختارها عند تصميم صورة أو قالب متوافق.

### ضوابط
- هذه الأداة لإدارة الهوية، وليست بالضرورة مولّد شعار؛ مولّد الشعار أداة مستقلة.
- لا تُطبّق التغييرات على ملفات قديمة تلقائيًا دون تأكيد.
- لا تستخدم خطوطًا أو شعارات محمية دون حق استخدام.
- إذا لم يكن ربط الهوية بالمحرر منفذًا، اجعلها مكتبة أصول فقط ووضّح ذلك.

## 12 — Créateur de logo | منشئ الشعارات

### الهدف
مساعدة المستخدم على إنشاء أفكار شعارات أولية، ثم تخصيص الرمز والألوان والنص والتكوين وتنزيل النتيجة بصيغ مناسبة.

### طريقة الاستخدام
1. يدخل اسم العلامة التجارية.
2. يضيف وصفًا اختياريًا للنشاط أو شخصية العلامة.
3. يختار أسلوبًا بصريًا أو ألوانًا عند توفر الخيارات.
4. يضغط «إنشاء أفكار».
5. يختار فكرة ويخصص النص واللون والحجم والترتيب إذا كانت أدوات التحرير متاحة.
6. يعاين الشعار على خلفية فاتحة وداكنة.
7. ينزّل الصيغ التي يدعمها النظام.

### خيارات واجهة ممكنة
- بسيط، هندسي، فاخر، طبيعي، تقني.
- لوحة ألوان.
- رمز/أيقونة.
- اسم العلامة وشعارها النصي.
- خلفية شفافة إذا كان التصدير يدعمها.
- تنزيل PNG أو SVG فقط إذا كان كل تنسيق يولّد بصورة صحيحة.

### ضوابط
- لا تَعِد بأن الشعار حصري أو مسجل قانونيًا.
- لا تدّعِ إنشاء SVG متجهي حقيقي إذا كانت النتيجة مجرد صورة نقطية داخل ملف SVG.
- أظهر تنبيهًا بأن على المستخدم التحقق من التشابه والعلامات التجارية قبل الاستخدام الرسمي.
- لا تستخدم شعارات علامات مشهورة كقوالب جاهزة.

## 13 — Traitement par lots | المعالجة الجماعية

### الهدف
تطبيق نفس الإجراء أو مجموعة إعدادات على عدة صور دفعة واحدة، بدل تكرار العمل لكل صورة يدويًا.

### طريقة الاستخدام
1. يختار المستخدم عدة صور أو يسحب مجموعة ملفات إلى منطقة الرفع.
2. يعرض النظام قائمة الصور المصغرة وحالة كل ملف.
3. يختار الإجراء الجماعي المتاح، مثل تغيير المقاس أو الصيغة أو تحسينات محددة أو إزالة الخلفية إذا كان المحرك يدعمها.
4. يحدد الإعدادات المشتركة.
5. يشاهد ملخصًا قبل التنفيذ.
6. يضغط «بدء المعالجة».
7. تظهر حالة كل صورة بشكل مستقل: في الانتظار، قيد المعالجة، ناجحة، فاشلة.
8. يستطيع إعادة محاولة الملفات الفاشلة فقط.
9. ينزّل الصور منفردة أو كملف ZIP إذا كان إنشاء ZIP مدعومًا.

### متطلبات
- لا تعالج آلاف الصور دفعة واحدة دون حدود تقنية معروفة؛ استخدم دفعات/طوابير حسب النظام.
- أظهر العدد الإجمالي والناجح والفاشل.
- لا تفقد الملفات الناجحة إذا فشل ملف واحد.
- لا تُعد إرسال الملف نفسه عدة مرات بسبب إعادة المحاولة.
- اعرض تقديرًا للتكلفة فقط عند وجود بيانات أسعار فعلية.
- وضّح الإجراءات المدعومة جماعيًا؛ ليست كل أداة فردية بالضرورة قابلة للتشغيل الجماعي.

## 14 — Catalogue de produits | كتالوج المنتجات

### الهدف
تنظيم صور منتجات المتجر وتجهيزها للعرض ككتالوج بصري متناسق، مع ربط الصورة بالمنتج إذا كانت بيانات الكتالوج متاحة.

### الوظائف المقترحة
- استيراد صور أو اختيار صور منتجات من مكتبة المتجر.
- عرض المنتجات في شبكة مع صورة مصغرة واسم/معرّف المنتج عند توفر البيانات.
- تصنيف المنتجات حسب الفئة.
- توحيد مقاس الصور ونسب الأبعاد.
- معاينة الصورة الأساسية والصور البديلة.
- تطبيق إعدادات موحدة على مجموعة صور إذا كانت المعالجة الجماعية مدعومة.
- تنزيل الصور أو تصدير قائمة/حزمة إذا كان النظام يدعم ذلك.

### طريقة الاستخدام
1. يختار المستخدم صور المنتجات أو يربط الكتالوج الموجود.
2. تظهر شبكة المنتجات.
3. يختار فئة أو مجموعة.
4. يحدد إعدادات الصور المشتركة.
5. يعاين النتائج.
6. يعتمد التعديلات وينزّلها أو يحفظها في الكتالوج إذا كان الربط منفذًا.

### ضوابط
- لا تخترع أسماء أو أسعارًا أو SKU للمنتجات.
- لا تغيّر الصور الأصلية في قاعدة البيانات دون تأكيد.
- فرّق بين «كتالوج صور» و«إدارة كتالوج تجارة إلكترونية كاملة»؛ لا تدّعِ إدارة المخزون أو الأسعار إذا لم تكن موجودة.
- وضّح حالة كل صورة وأي منتج لا توجد له صورة.

## 15 — Capture d'objet | التقاط عنصر من الصورة

### الهدف
تمكين المستخدم من اختيار عنصر داخل صورة، وفصله عن موضعه الأصلي، ثم نقله أو تغيير حجمه أو تدويره بشكل مستقل، مع الحفاظ على الخلفية الأصلية قدر الإمكان. هذه الوظيفة مختلفة عن إزالة الخلفية وحذف العناصر.

### الفرق بين الأدوات
- **Capture d'objet:** يعزل عنصرًا داخل الصورة ليصبح قابلًا للتحريك والتعديل؛ يُفترض معالجة المكان الذي تركه العنصر في الخلفية.
- **Suppression de fond:** يزيل الخلفية من الموضوع الرئيسي أو المحدد.
- **Supprimer des objets:** يحذف عنصرًا غير مرغوب فيه ويعيد بناء المنطقة التي كان يشغلها.

### طريقة الاستخدام
1. يرفع المستخدم صورة غير موجودة داخل إطار/شبكة، إذا كان محرك الالتقاط لا يدعم الصور المؤطرة.
2. يختار «تحديد بالنقر» ثم ينقر على العنصر، أو يختار «الفرشاة» ويرسم فوقه.
3. يمكنه إضافة عناصر متعددة للتحديد أو إزالة مناطق غير صحيحة.
4. يضغط «التقاط العنصر».
5. يفصل المحرك العنصر عن الخلفية وينشئ طبقة مستقلة.
6. تُعالج المنطقة التي كان العنصر يشغلها لإعادة بناء الخلفية، إن كان المحرك يدعم ذلك.
7. يظهر العنصر كطبقة قابلة للسحب والتحريك وتغيير الحجم والتدوير.
8. يستطيع المستخدم تكرار العنصر أو حذفه من التصميم إذا كانت هذه الوظائف متاحة.
9. يضغط «تطبيق» ثم يحفظ نسخة جديدة أو ينزّلها.

### عناصر التحكم
- تحديد بالنقر.
- فرشاة تحديد بحجم قابل للتغيير.
- تكبير وتحريك مساحة العمل.
- مسح التحديد وإعادة البدء.
- التقاط العنصر.
- مقابض لتغيير الحجم والتدوير.
- سحب العنصر بالماوس أو اللمس.
- تراجع/إعادة.
- مقارنة قبل/بعد.
- إعادة الصورة إلى الحالة الأصلية.

### متطلبات تقنية
- حافظ على إحداثيات التحديد عند التكبير والتحريك.
- اجعل التحكم مناسبًا للفأرة واللمس.
- لا تسمح بتمرير الصفحة أثناء السحب داخل مساحة العمل على الهاتف إذا كان ذلك يفسد التفاعل.
- اعرض حدود العنصر المحدد بوضوح.
- إذا كان فصل العنصر أو ملء الخلفية يعتمد على API، فاعرض حالة المعالجة والأخطاء والتكلفة الفعلية قبل التنفيذ.
- لا تستخدم مجرد مستطيل قصّ حول العنصر وتسمّه التقاطًا ذكيًا.
- لا تعرض نتيجة وهمية. إذا كانت الميزة غير موصولة بمحرك الفصل وإعادة بناء الخلفية، اعرض «قريبًا» أو نفّذ واجهة اختيار فقط بوضوح.
- لا تعد بأن كل عنصر في كل صورة قابل للاستخراج بدقة كاملة.

# 3. قواعد مشتركة للصور والتصدير

- اعرض معاينة للصورة قبل المعالجة.
- لا تقلّل جودة الأصل بصمت.
- حافظ على الشفافية عند تصدير PNG إذا كانت موجودة.
- عند التصدير إلى JPEG، نبّه المستخدم إلى أن الشفافية ستُستبدل بخلفية.
- استخدم أسماء ملفات واضحة وتجنب الكتابة فوق الأصل.
- أظهر أبعاد الصورة وحجم الملف إن كان ذلك مفيدًا.
- تأكد من اتجاه الصور وبيانات EXIF، وتجنب عرض صور ملتفة بسبب بيانات الاتجاه.
- تعامل مع الصور الكبيرة بطريقة لا تجمّد الواجهة؛ استخدم Web Worker أو معالجة خادمية إذا كانت مناسبة للبنية الحالية.
- وفّر تنزيلًا فعليًا للنتيجة، لا زرًا شكليًا.

# 4. الحالات المشتركة في الواجهة

لكل أداة، عالج الحالات التالية:
- لم تُرفع صورة بعد.
- الصورة جاهزة.
- تحقق من الملف.
- قيد الرفع.
- قيد المعالجة.
- اكتملت المعالجة.
- فشل التنفيذ.
- انقطع الاتصال.
- نفدت الحصة/الرصيد، إذا كان النظام يدعم ذلك فعلًا.
- ألغى المستخدم العملية.
- النتيجة غير صالحة أو فارغة.
- تنزيل النتيجة.

# 5. معايير القبول

لا تعتبر الأداة مكتملة حتى:
1. يمكن الوصول إليها من مركز الأدوات ومن رابط مباشر.
2. تعمل على الهاتف والحاسوب.
3. جميع الأزرار إما فعالة أو معطلة مع توضيح السبب.
4. توجد معالجة فعلية أو بيان صريح بأن محركها غير مفعّل.
5. لا يُفقد الأصل.
6. تعمل رسائل الخطأ وحالات التحميل.
7. يمكن تنزيل النتيجة عند نجاح المعالجة.
8. لا توجد نصوص واجهة مطبوعة داخل الصور.
9. لا توجد أسعار أو ميزات مخترعة.
10. توجد اختبارات للحالات الأساسية.
11. تتوافق الأداة مع نظام المصادقة والتخزين الموجود في Alyssum.
12. لا تُكشف مفاتيح API في كود العميل.

# 6. ترتيب التنفيذ المقترح

نفّذ الأدوات على مراحل حسب المحركات المتوفرة:
1. **أساسيات محلية:** تغيير المقاس، إطار/هوية بصرية، إعدادات الصور، وإدارة صور الكتالوج، حسب ما يدعمه المشروع.
2. **أدوات صور تحتاج نماذج متخصصة:** إزالة الخلفية، حذف العناصر، إعادة التلوين، التقاط العناصر.
3. **أدوات توليد:** مولّد الصور، تصوير المنتج، وضع المنتج في مشهد، توسيع الصورة، توليد الفيديو.
4. **أدوات أزياء:** النموذج الافتراضي والتجربة الافتراضية.
5. **أدوات تدفق العمل:** المعالجة الجماعية وربطها بالأدوات التي تسمح محركاتها بمعالجة دفعات.

لا تبدأ بإظهار جميع الأدوات كأنها مكتملة قبل التأكد من وجود محرك فعلي لكل أداة.

# 7. طلب التنفيذ النهائي إلى Claude

اقرأ هذا الملف كاملًا، ثم افحص مشروع Alyssum الحالي. أنشئ خطة تنفيذ قصيرة تحدد الملفات والمكونات والخدمات التي ستتغير، وتوضح لكل أداة ما هو موجود بالفعل وما يحتاج إلى محرك أو API إضافي. بعد ذلك نفّذ العمل تدريجيًا دون كسر الوظائف الحالية. التزم بالتصميم الحالي للمنصة، وباللغة العربية RTL، وبالأصول والصور التي زوّدك بها المستخدم. لا تستبدل الصور أو تخترع قدرات أو أسعارًا. اختبر كل أداة وسجّل أي وظيفة لا يمكن تنفيذها ضمن البنية أو الخدمات المتاحة.

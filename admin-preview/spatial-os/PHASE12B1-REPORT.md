## 4) الدلالات قبل/بعد
| الحالة | قبل | بعد |
|---|---|---|
| 5xx / انقطاع شبكة / JSON ناقص | `{ok:true}` ← «تم تسجيل طلبك» + واتساب | `SERVER_ERROR`/`UNKNOWN`/`INVALID_RESPONSE` ← نافذة «لم يُؤكَّد»، نموذج محفوظ، لا نجاح |
| 200 بلا `ok`/معرّف أو معرّف مشوَّه | نجاح | `INVALID_RESPONSE` |
| 200 + `ok:false` | يختلف | `REJECTED` (مع error) أو `INVALID_RESPONSE` |
| 4xx | نجاح ضمني في بعض المسارات | `REJECTED` (رسالة سبب، النموذج باقٍ) |
| ضياع الردّ بعد الحفظ | طلب مكرّر أو «نجاح» كاذب | إعادة بنفس المفتاح ← `DUPLICATE_CONFIRMED` بمعرّف الأصل |
| المعرّف | قد يُختلق محلياً | من الخادم فقط وبصيغة صالحة |
| الأحجام | مفتاح من djb 32-بت/`Math.random` | SHA-256 كاملة بملح تبويب + `randomUUID`/`getRandomValues`؛ تعذّر العشوائية ← لا إرسال |

## 5) تصميم idempotency ودورة حياة المفتاح
- **البصمة:** تسلسل JSON ثابت الترتيب (إصدار `v1`) لـ: الاسم (مسافات مطبَّعة) · الهاتف (أرقام، `+213/00213/213`→`0`) · الولاية · البلدية · نوع التوصيل · المكتب · البنود (slug + العنوان بالتنويع + الكمية + سعر الوحدة، مرتَّبة) · المجموع الفرعي · الرسوم · الخصم · الكوبون/الترويج · الإجمالي · extra التجاري. مستثنى عمداً: `🔗 مرجع` و`🧺 مجموعة` (يتولّدان لكل محاولة) وحقول مكافحة الروبوت (`hp`,`ftok`,`ctoken`).
- **المفتاح:** عشوائي آمن (32 hex)، يُربط بتجزئة SHA-256 مملّحة للبصمة في `sessionStorage` (نطاق التبويب؛ ملح لكل تبويب ← تبويبان لا يتشاركان مفتاحاً). لا PII في التخزين (مُتحقَّق).
- **إعادة الاستعمال:** نفس البصمة ← نفس المفتاح عبر UNKNOWN/SERVER_ERROR/INVALID_RESPONSE؛ تغيّر أي حقل تجاري ← مفتاح جديد.
- **المسح:** عند CONFIRMED/DUPLICATE_CONFIRMED/REJECTED فقط. **الانتهاء:** 30 دقيقة في العميل (تنظيف `purge` عند الاستعمال)؛ 7 أيام في الخادم (تنظيف احتمالي ~1/50 عند الإدراج).
- **الخادم (PHP):** الردّ من المفتاح قبل الحراس/حدّ المعدّل؛ `BEGIN IMMEDIATE` يعيد الفحص داخل المعاملة؛ نفس المفتاح بمحتوى مختلف ← 409 `idempotency_key_reuse`؛ مفتاح غير صالح ← 422؛ سجلّ idem في قاعدة كل متجر (لا تقاطع مستأجرين)؛ الإدراج ضمن معاملة الطلب (يتراجعان معاً).
